# Home Rehab Motion 本地启动运行指南

## 1. 适用范围

本文用于本地开发、联调和功能验证。服务包括：

- 患者端微信小程序：`apps/patient-miniapp`
- 管理端 Web：`apps/admin-web`
- 主服务：`services/main-service`
- 分析 API 与 Celery Worker：`services/analysis-service`
- MySQL、Redis、MinIO：本地依赖环境

## 2. 前置条件

- Node.js 20 LTS（项目运行环境；当前 Node 16 虽可安装部分依赖，但会出现兼容性告警）
- npm
- Python 3.11（分析服务推荐版本）
- Docker Desktop（推荐，用于 MySQL、Redis、MinIO）或本机已启动 MySQL 与 Redis
- 微信开发者工具（用于患者端）

首次安装 Node 依赖：

```bash
nvm install
nvm use
npm ci
```

项目通过 `.nvmrc` 固定 Node.js 20；启动脚本也会在低于 20 时终止，避免因 Node.js 16 产生依赖兼容性与 Prisma 生成问题。

启动本地依赖：

```bash
docker-compose -f infra/docker-compose.local.yml up -d
```

本机当前安装的是独立版 Docker Compose（`docker-compose`），没有 Docker Compose Plugin，因此 `docker compose` 会报 `docker: unknown command: docker compose`，并将 `-f` 当作 Docker 的参数，从而出现 `unknown shorthand flag: 'f' in -f`。如已安装 Compose Plugin，也可以使用等价命令：

```bash
docker compose -f infra/docker-compose.local.yml up -d
```

检查依赖容器状态：

```bash
docker-compose -f infra/docker-compose.local.yml ps
```

如果使用本机服务，需要保证：

- MySQL：`127.0.0.1:3306`，数据库 `home_rehab_motion`
- Redis：`127.0.0.1:6379`
- MinIO：`127.0.0.1:9000`，控制台 `127.0.0.1:9001`

## 3. 本地环境变量

根目录 `.env` 是本地联调配置。关键值：

- `PORT=3000`：主服务端口
- `ANALYSIS_PORT=8001`：分析 API 端口
- `ANALYSIS_SERVICE_URL=http://127.0.0.1:8001`
- `ANALYSIS_CALLBACK_URL=http://127.0.0.1:3000/api/videos/internal/analysis-callback`
- `MOCK_AUTH_FALLBACK=true`：仅本地允许微信登录 Mock 回退
- `STORAGE_UPLOAD_MODE=s3_post`：小程序直传本地 MinIO

本地 `.env` 不可用于线上，尤其不能复用默认 token、Mock 开关和 HTTP 地址。

## 4. 标准启动方式

```bash
./start-local.sh
```

脚本会依次：

1. 检查 MySQL 与 Redis；
2. 自动执行已提交的 Prisma 数据库迁移；
3. 创建分析服务 Python 虚拟环境（首次）并安装依赖；
4. 启动主服务、分析 API、Celery Worker、Celery Beat 和管理端。

启动地址：

- 管理端：`http://127.0.0.1:5173`
- 主服务：`http://127.0.0.1:3000/api`
- 主服务存活探针：`http://127.0.0.1:3000/api/health/live`
- 主服务就绪探针：`http://127.0.0.1:3000/api/health/ready`
- 分析服务：`http://127.0.0.1:8001`
- 分析存活探针：`http://127.0.0.1:8001/health/live`

按模块启动：

```bash
./start-local.sh main
./start-local.sh analysis
./start-local.sh admin
```

停止所有服务：

```bash
./start-local.sh stop
```

## 5. 首次启动或更新代码后

当拉取了包含 `services/main-service/prisma/migrations` 的改动时，必须先执行迁移。脚本会自动执行；若单独操作：

```bash
npx prisma migrate deploy --schema services/main-service/prisma/schema.prisma
npx prisma generate --schema services/main-service/prisma/schema.prisma
```

更新后服务未自动恢复、端口无响应或出现旧接口行为时，执行完整重启：

```bash
./start-local.sh stop
./start-local.sh
```

检查迁移状态：

```bash
npx prisma migrate status --schema services/main-service/prisma/schema.prisma
```

### 首次初始化对象存储

Compose 只负责启动 MinIO，不会自动创建桶。当前 `.env` 使用 `STORAGE_UPLOAD_MODE=s3_post`，因此首次启动后必须创建 `home-rehab-motion-assets` 桶：

```bash
docker run --rm --entrypoint /bin/sh minio/mc -c \
  'mc alias set local http://host.docker.internal:9000 minioadmin minioadmin && mc mb --ignore-existing local/home-rehab-motion-assets'
```

也可以访问 `http://127.0.0.1:9001`，使用账号和密码 `minioadmin` 登录后，在控制台手动创建同名桶。仅用于本地开发的直传调试时，可将桶访问策略设为 `download`；生产环境必须使用独立账号和最小权限策略，不应公开桶。

## 6. 本地登录体系

### 患者端小程序

患者端通过 `wx.login()` 获取微信临时 `code`，调用：

```text
POST /api/auth/wx-login
```

后端在正式环境用 `WX_APP_ID`、`WX_APP_SECRET` 调微信 `jscode2session`，以 `openid` 唯一识别患者，签发 7 天有效的 HMAC 签名 Bearer Token。

本地 `.env` 未配置微信参数且 `MOCK_AUTH_FALLBACK=true`，会用 `mock-openid:<code>` 创建或复用本地测试患者。这是本地便利能力，生产环境禁止开启。

患者 Token 保存在小程序本地存储，后续请求自动携带：

```text
Authorization: Bearer <token>
```

患者首次上传训练视频前需要在“我的 → 隐私政策”同意视频分析授权；撤回后会停止后续上传和分析。

### 管理端 Web

管理端使用数据库 `admin_account` 中已存在的账号密码，调用：

```text
POST /api/admin/auth/login
```

密码以 `scrypt` 哈希保存，后端验证成功后签发同一格式的 HMAC Bearer Token。前端保存至浏览器 `localStorage` 的 `admin_token` 与 `admin_role`，请求自动携带授权头。

生产环境没有 `admin / 任意密码` 或 `nurse / 任意密码` 的后门。首次创建管理员只能显式执行：

```bash
BOOTSTRAP_ADMIN_USERNAME=admin \
BOOTSTRAP_ADMIN_PASSWORD='至少12位的强密码' \
BOOTSTRAP_ADMIN_DISPLAY_NAME='初始管理员' \
npm run bootstrap:admin -w @home-rehab-motion/main-service
```

该命令仅在不存在任何管理账号时允许执行一次。

## 7. 常见故障排查

### `unknown shorthand flag: 'f' in -f` 或 `docker: unknown command: docker compose`

这表示当前 Docker 安装没有 Compose Plugin。请使用独立版命令，而不是 `docker compose`：

```bash
docker-compose -f infra/docker-compose.local.yml up -d
docker-compose -f infra/docker-compose.local.yml ps
```

如果 `docker-compose` 也不存在，则需要在 Docker Desktop 设置中安装或启用 Compose Plugin，之后使用 `docker compose ...`。

### 管理端页面所有接口都失败

先验证主服务：

```bash
curl -i http://127.0.0.1:3000/api/health/live
```

若连接被拒绝，主服务未启动；执行：

```bash
./start-local.sh stop
./start-local.sh
```

管理端 Vite 只做代理，主服务离线时会在浏览器或 `admin-web.log` 中出现：

```text
ECONNREFUSED 127.0.0.1:3000
```

### 新增接口报“表不存在”

说明数据库迁移未应用：

```bash
npx prisma migrate deploy --schema services/main-service/prisma/schema.prisma
./start-local.sh stop
./start-local.sh
```

### 端口被旧进程占用

```bash
./start-local.sh stop
lsof -nP -iTCP:3000 -sTCP:LISTEN
lsof -nP -iTCP:8001 -sTCP:LISTEN
lsof -nP -iTCP:5173 -sTCP:LISTEN
```

如仍有残留进程，先停止对应 PID，再重新执行启动脚本。

### 服务日志

```bash
tail -f .local-logs/main.log
tail -f .local-logs/analysis-api.log
tail -f .local-logs/analysis-worker.log
tail -f .local-logs/analysis-beat.log
tail -f .local-logs/admin-web.log
```
