# Home Rehab Motion 仓库目录与文件说明

> 本文说明仓库内各目录、关键文件、运行方式及 Git 提交边界。
>
> 当前代码内部仍有部分历史 `health1` 标识（例如 npm 包名、数据库默认名、存储目录和页面品牌）。它们不影响本说明中所描述的架构；后续若创建全新的 `home-rehab-motion` 仓库，可作为独立重命名任务统一迁移。

## 1. 仓库整体职责

这是一个面向居家康复训练的 monorepo，包含：

- 患者端微信小程序；
- 医护/运营使用的管理端 Web；
- 业务主服务；
- 视频动作分析 API 和异步 Worker；
- 共享的接口契约、类型、常量；
- Docker 部署编排、数据库迁移、产品和技术资料。

核心链路如下：

```text
患者小程序 / 管理端 Web
          │ HTTPS / HTTP API
          ▼
main-service（业务、登录、上传、报告、管理）
          │ 内网 HTTP：创建/查询分析任务
          ▼
analysis-service（FastAPI）
          │ Redis / Celery 队列
          ▼
analysis-worker（视频抽帧、姿态估计、评分）
          │ HTTPS 回调
          ▼
main-service 写入 MySQL，患者端轮询并展示报告
```

MySQL 是业务结果的最终来源；Redis 用于异步分析队列和短期任务状态；对象存储保存视频、图片等资产。

#### API 与 Worker 的分工

- `analysis-service`：仅提供内部 HTTP API，快速创建任务或返回任务状态；不应执行耗时视频推理。
- `analysis-worker`：消费 Redis 中的 `analysis` 队列，执行抽帧、姿态估计、评分、结果写库或回调。
- `analysis-beat`：本地启动脚本中额外启动。当前 Celery 已配置每分钟重试待投递回调任务，因此生产环境也应部署一个单实例 Beat，或用等效的受控定时调度替代，不能与 Worker/API 混为一谈。

如果只部署 API、未部署 Worker，视频任务会持续停留在“分析中”。

## 9. 环境变量与配置优先级

### 9.1 本地推荐方式

推荐只维护根目录 `.env`：

```text
项目根目录/.env                 唯一真实本地配置（不提交）
项目根目录/.env.example         完整模板（提交）
services/analysis-service/.env.example  分析服务独立启动的参考模板（提交）
```

执行 `./start-local.sh` 时，脚本会先加载根目录 `.env`，然后启动主服务、分析 API、Worker、Beat 和管理端。

分析服务代码也兼容读取根 `.env` 和当前目录 `.env`，但若两处同名变量不同，会造成认知混乱。因此建议不要维护 `services/analysis-service/.env`。

### 9.2 生产方式

生产容器不依赖仓库内 `.env`：

1. 在阿里云服务器或 Secret Manager 保存生产密钥；
2. 使用 `docker compose --env-file /安全路径/production.env ...` 注入；
3. `main-service`、`analysis-service`、`analysis-worker` 从容器环境变量读取配置；
4. 不将 `.env`、AccessKey、数据库密码、微信 Secret 提交 Git 或打入镜像。

## 10. `.gitignore` 已覆盖的内容

当前 `.gitignore` 会忽略：

- Node/Python 依赖与缓存：`node_modules/`、`.venv/`、`__pycache__/`、`.pytest_cache/`；
- 构建产物：`dist/`、`build/`、`coverage/`、`.vite/`；
- 本地状态：`.local-logs/`、`.local-pids/`、`.local-storage/`、`*.log`、`*.pid`；
- 本地数据库和 Celery 状态：`dev.db`、`celerybeat-schedule*`；
- 真实环境文件：所有 `.env`/`.env.*`，但保留 `.env.example`；
- 本地 IDE/微信私有配置：`.idea/`、`.vscode/`、`.DS_Store`、`project.private.config.json`。

注意：如果某个文件已经被 Git 追踪，后来再加入 `.gitignore` 不会自动停止追踪；需要确认并将其从 Git 索引移除，但保留本地文件。

## 12. 常用操作

```bash

docker compose -f infra/docker-compose.local.yml up -d

# 启动主服务、分析 API、Worker、Beat、管理端
./start-local.sh

# 说明：本地 Compose 项目名称已指定为 home-rehab-motion；若本机 Docker 版本不支持 Compose 的 name 字段，请升级 Docker Compose Plugin 后再启动。

# 仅启动业务主服务
./start-local.sh main

# 仅启动分析 API 与 Worker
./start-local.sh analysis

# 停止本地后台服务
./start-local.sh stop

# 工作区 TypeScript 检查
npm run typecheck

# 查看主服务日志
tail -f .local-logs/main.log

# 查看分析 Worker 日志
tail -f .local-logs/analysis-worker.log
```

患者小程序不由上述脚本直接启动：使用微信开发者工具打开 `apps/patient-miniapp`。
