# Home Rehab Motion 线上发布运行指南

## 1. 适用范围与原则

本文说明 staging / production 的标准发布与运行方式。生产环境必须使用：

- HTTPS Ingress / 负载均衡；
- 私网 MySQL、Redis、分析 API 与 Worker；
- 私有对象存储与短期预签名 URL；
- Secret Manager 或等效运行时密钥注入；
- 不可变容器镜像、数据库迁移门禁、健康检查和可回滚部署。

不要将本地 `.env`、本地 Compose 或 Mock 登录配置复制到线上。

## 2. 部署单元

生产编排基线位于：

```text
infra/docker-compose.production.yml
```

部署单元如下：

| 服务 | 职责 | 网络暴露 |
|---|---|---|
| `admin-web` | 管理端静态站点 | 仅通过 HTTPS Ingress |
| `main-service` | API、鉴权、业务状态、回调写入 | 仅通过 HTTPS Ingress |
| `analysis-service` | 分析任务提交与查询 API | 内网 |
| `analysis-worker` | Celery 视频分析任务 | 内网 |
| MySQL | 业务、任务、授权、审计数据 | 内网 |
| Redis | Celery Broker / 短期任务状态 | 内网 |
| 对象存储 | 患者视频、反馈图片、分析资产 | 私有 Bucket |

正式环境优先用 Kubernetes/Helm 或云平台编排。`docker-compose.production.yml` 用于受控演练、staging 基线和环境变量校验，不应替代云上网络、安全组、KMS 与备份策略。

## 3. 发布前准备

### 3.1 环境隔离

至少建立独立的 `development`、`staging`、`production`：

- 独立 MySQL、Redis、对象存储 Bucket、密钥、域名和监控空间；
- staging 使用模拟或脱敏数据；
- 禁止通过生产数据验证 staging；
- 生产数据库账号最小权限，应用账号不得使用 root。

### 3.2 必填密钥与配置

所有密钥从 Secret Manager/KMS 注入容器运行环境，禁止写入 Git、镜像和前端包。

| 配置 | 要求 |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | 指向私网 MySQL |
| `REDIS_URL` | 指向带认证的私网 Redis |
| `AUTH_TOKEN_SECRET` | 至少 32 位、非默认值 |
| `ANALYSIS_INTERNAL_TOKEN` | 至少 32 位、非默认值 |
| `WX_APP_ID` / `WX_APP_SECRET` | 正式微信小程序凭据 |
| `ANALYSIS_CALLBACK_URL` | 公网 HTTPS 回调地址 |
| `PUBLIC_API_BASE_URL` | 公网 HTTPS API 地址 |
| `OSS_ENDPOINT` | HTTPS 私有对象存储 Endpoint |
| `OSS_BUCKET` | 非公开患者资产 Bucket |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | 最小权限访问凭据或等价工作负载身份 |
| `STORAGE_UPLOAD_MODE` | `s3_post` |

生产启动会拒绝：Mock 登录、legacy Mock Token、样例视频/Mock 关键点回退、默认密钥、HTTP 回调、公共对象存储回退、本地代理上传等配置。

## 4. 标准发布流程

### 4.1 CI 质量门禁

推送代码或创建合并请求后，CI 工作流 `.github/workflows/ci.yml` 会执行：

1. 安装 Node 依赖并进行全工作区类型检查；
2. 构建主服务与管理端；
3. 安装 Python 依赖并编译检查分析服务；
4. 扫描默认密钥与开发 Mock 开关；
5. 校验生产 Compose 必填变量；
6. 构建三个容器镜像。

所有门禁成功后才能进入 staging。

### 4.2 构建镜像

镜像入口文件：

```text
services/main-service/Dockerfile
services/analysis-service/Dockerfile
apps/admin-web/Dockerfile
```

镜像标签应包含不可变版本，例如 Git commit SHA：

```text
registry.example/home_rehab_motion/main-service:<commit-sha>
registry.example/home_rehab_motion/analysis-service:<commit-sha>
registry.example/home_rehab_motion/admin-web:<commit-sha>
```

部署前还应由镜像仓库或安全平台执行依赖与镜像漏洞扫描；高危漏洞未关闭时阻断发布。

### 4.3 数据库迁移

迁移必须在应用新版本接流量前执行，且先完成备份：

```bash
npx prisma migrate deploy --schema services/main-service/prisma/schema.prisma
```

发布顺序：

1. 创建 MySQL 备份并确认可恢复；
2. 在 staging 运行迁移并验证；
3. 在生产窗口运行 `prisma migrate deploy`；
4. 确认迁移状态；
5. 再滚动发布应用与 Worker。

禁止在生产使用 `prisma migrate dev`。

### 4.4 Staging 验证

发布 staging 后检查：

```bash
curl -fsS https://staging-api.example.com/api/health/live
curl -fsS https://staging-api.example.com/api/health/ready
curl -fsS http://analysis-service:8000/health/live
curl -fsS http://analysis-service:8000/health/ready
```

业务验证至少覆盖：

1. 患者微信登录与授权；
2. 隐私授权后上传、分析、报告；
3. 撤回授权后上传被拒绝；
4. 质量不足、人工复核和重复回调场景；
5. 管理员登录、患者详情、视频详情、反馈详情；
6. 审计表中能查到敏感访问记录。

### 4.5 生产发布与灰度

推荐：

1. 人工审批发布；
2. 先部署 Worker / 分析服务，再部署 main-service，最后部署管理端；
3. 以 5% → 20% → 100% 流量灰度；
4. 每阶段观察 API 错误率、P95、队列积压、分析失败率、回调重试/死信、数据库连接和授权拒绝异常；
5. 任一关键指标异常立即停止扩大范围并回滚镜像。

## 5. 运行与运维

### 5.1 健康检查

| 地址 | 用途 |
|---|---|
| `/api/health/live` | 主服务进程存活 |
| `/api/health/ready` | 主服务 + MySQL 就绪 |
| `/health/live` | 分析 API 存活 |
| `/health/ready` | 分析 API + MySQL 就绪 |

Ingress 或 Kubernetes 应将存活与就绪探针分别配置，不能仅按端口监听判断服务可用。

### 5.2 日志、指标与审计

- 生产分析服务输出 JSON 日志；
- 主服务、分析服务和 Worker 日志统一汇聚，保留 `traceId`、视频 ID、任务 ID、回调状态；
- 重点告警：API 错误率、认证失败、队列积压、分析失败率、回调死信、报告不可用、MySQL/Redis 不可用、备份失败、证书过期；
- 敏感访问审计记录写入 `sensitive_access_audit`，包含操作者、资源、患者、来源 IP、User-Agent 与时间。

### 5.3 备份与恢复

- MySQL：加密备份、定期恢复演练；
- 对象存储：版本控制、生命周期与异地/异账号备份；
- Redis：AOF 持久化；任务最终状态仍以 MySQL/outbox 和补偿为准；
- 数据库迁移前强制备份；
- 在演练环境验证恢复后的 API、登录、报告和分析补偿能力。

## 6. 回滚

应用回滚：

1. 停止灰度扩大；
2. 将 main-service、analysis-service、analysis-worker、admin-web 回滚到上一个健康镜像标签；
3. 检查 `/live` 与 `/ready`；
4. 观察回调补偿和队列积压是否恢复。

数据库迁移不可默认自动回滚。发生数据问题时按迁移前备份、恢复演练方案处理，并由数据库责任人执行。

## 7. 生产登录体系

### 患者端

- 微信小程序 `wx.login()` 获取 code；
- 后端调用微信 `jscode2session` 获取 `openid`；
- 后端按 `openid` 创建或查找患者档案；
- 签发 HMAC Bearer Token；
- 患者须同意隐私和视频分析授权才可上传与分析。

### 管理端

- 仅数据库中的 `admin_account` 可登录；
- 密码使用 `scrypt` 哈希验证；
- 角色仅为 `admin` 或 `nurse`，从数据库读取；
- 初始管理员在首次部署时通过受控一次性引导创建；
- 不提供默认账户、任意密码登录或 Mock Token。

## 8. 上线拒绝条件

禁止生产发布的典型情况：

- CI 核心门禁失败；
- 数据库迁移未验证或无备份；
- Mock、默认密钥、HTTP 外部地址、公开患者 Bucket；
- 健康检查、监控、告警或审计未就绪；
- 隐私授权、撤回后的上传拦截未验证；
- 高危安全漏洞未关闭；
- 临床/医疗边界、个人信息与患者开放审批未完成。
