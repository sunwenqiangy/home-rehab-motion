# 安舒随行当前实现口径

> 更新时间：2026-10-23
>
> 本文是产品、管理端、微信小程序和后端实现之间的对齐入口。与历史方案冲突时，以代码和本文为准；算法参数的最终运行值以部署环境变量和分析结果快照为准。
>
> **运行配置提醒**：代码默认值、根目录 `.env.example` 和生产 Compose 的缺省值并不完全一致，特别是缩腹的视觉评分模式。发布/验收必须记录 Worker 实际生效的 `ABDOMINAL_SEGMENTATION_MODE`、`ABDOMINAL_VISUAL_SCORE_MODE`、`KNEE_ROTATION_MODE`；不能仅凭某一份文档或 Compose 缺省值推断线上结果。

## 1. 产品边界

安舒随行是居家动作训练与记录工具。视频用于观察动作完成情况、生成训练反馈和留痕激励，不要求用户上传完整训练过程，也不输出医疗诊断、治疗方案或精确临床测量结论。

当前支持三类动作：

| 动作类型 | 展示名称 | 主要用途 |
|---|---|---|
| `abdominal_crunch` | 缩腹运动 | 观察腹部/躯干运动代理、完整动作和练习节奏 |
| `pelvic_tilt` | 骨盆倾斜 | 观察骨盆后倾—回中立的可见闭环 |
| `knee_rotation` | 膝关节旋转 | 观察双膝双向运动和左右控制 |

## 2. 动作指导内容

### 2.1 管理端保存与启用

- 编辑页只有“保存内容”流程，不再提供可见的“保存草稿”流程。
- 点击保存时校验必填项；校验通过后直接生成新的内容版本，内容默认下线。
- 管理端列表中的“启用/下线”决定患者端是否展示；未启用的已保存版本不会影响患者端。
- 数据表中的 `draft_snapshot` 仍保留，用于兼容历史数据读取，不代表当前编辑流程仍支持草稿。
- 编辑已发布内容时，以当前已发布版本为编辑基线，不能被历史草稿标题覆盖。

### 2.2 当前必填项

| 模块 | 必填内容 |
|---|---|
| 基础信息 | 动作类型、标题、一句话目标、训练建议、封面图、训练前安全提示 |
| 教学视频 | 教学视频 |
| 动作步骤 | 3–5 个步骤；每个步骤必须有标题 |
| 拍摄要求 | 至少 1 条；每条必须有标题、患者短说明和正确示意图 |
| 常见错误 | 可选；填写后必须同时有错误说明、正确做法和至少一张示意图 |

“预计训练时长”字段仍保留在接口和数据快照中，但当前管理端隐藏，患者端不展示；新建内容使用默认值 3 分钟，仅作为兼容字段。

### 2.3 患者端展示顺序

动作指导详情页按以下顺序展示：动作概览 → 训练建议 → 开始前安全提示 → 教学视频 → 动作步骤 → 拍摄要求 → 常见错误 → 拍摄训练片段 / 从相册选择。

管理端预览应保持相同的信息顺序和字段语义；预览是编辑态模拟，真实展示以小程序页面为准。

## 3. 上传、分析与训练记录

- 普通视频只用于动作观察，患者无需上传完整训练过程。
- 小程序短片段上传上限由患者端配置和动作硬上限共同决定：缩腹、骨盆最多 30 秒，膝关节最多 60 秒。
- 当前患者端配置项为：自主记录开关、视频最短时长、相册视频最长时长、录制最长时长、视频大小上限、每周目标天数、可用动作类型。
- 管理端不再配置“分析中最短等待（秒）”。`estimatedWaitSeconds` 是接口运行时提示：确认上传成功通常返回 30 秒；一次同步投递失败、等待后台补投时返回 60 秒；状态查询中排队/处理中返回 30 秒。它不是业务配置项，也不是完成承诺。
- 视频确认上传后立即计入训练留痕；分析结果随后异步生成。质量不足或待复核时保留训练记录，但不展示确定性动作评分。
- 自主记录由管理端开关控制；开启时每天最多创建一条自主练习记录，已有记录始终可以查看。

## 4. 报告、阶段与激励

- 单次报告使用本段评分、有效次数、动作观察、建议和回放表达本次训练表现。
- 长期旅程阶段来自累计训练和训练周期，不由单次分数直接升降。
- 激励规则配置只包含当前服务端实际读取的 6 个阈值：综合分、稳定性、平均保持时间的轻微/明显进步阈值。
- 激励配置只影响后续训练结果，不回写历史报告快照。
- `review_required`、`quality_insufficient` 和失败结果不应被解释为用户动作做错；患者端展示原因和下一步操作。

### 4.1 当前激励规则与适用边界

- 训练日：视频**确认上传**即形成训练留痕；同一上海自然日只计一个训练日。自主记录开启后也可创建每天一条记录，若当日已有训练日则不重复计天。
- 长期旅程：当前阶段只由累计训练次数与自首次训练起的周数决定：默认“纠正期”；满 3 周且至少 4 次训练为“巩固期”；满 5 周且至少 8 次训练为“激励期”。它不由单次分数升降。
- 徽章：训练日/连续天数触发初次尝试、连续 3/7 天、累计 30/60/90 天；非短片段视频首次“优秀”可触发“首次优秀”。缩腹短片段不因分析完成自动发徽章。
- 同动作进步：仅在可比记录间比较综合分、稳定性、平均保持时长，按当前 6 个阈值判定轻微/明显进步。视觉缩腹证据分不推断康复进步；短片段还要求同动作、同分析/模板/切分版本、质量通过、置信度 ≥0.75、至少 1 个有效周期且未使用人工覆盖，才参与趋势比较。
- 页面实际展示的状态与话术矩阵见[产品视角：产品能力与用户旅程](../项目梳理/产品视角_产品能力与用户旅程.md)第 8 节；这里定义规则边界，产品文档定义患者可见表达。

## 5. 当前分析路径与版本边界

三种动作并非始终走同一种“关键点模板四维评分”。当前实现按动作、来源和运行开关分流：

| 场景 | 正式计次/评分路径 | 患者端展示边界 |
| --- | --- | --- |
| 小程序缩腹短片段，且 `ABDOMINAL_SEGMENTATION_MODE=shadow` | 腹壁视觉完整周期；`ABDOMINAL_VISUAL_SCORE_MODE=evidence` 时为视觉证据规则分 | 仅说明本段视频；未评分不等于 0 分或未练习；不用于康复进步推断 |
| 缩腹非上述条件或回退模式 | 姿态关键点峰值/闭环路径与模板评分 | 模板或特征口径不兼容时转待复核，不展示确定性分数 |
| 骨盆倾斜 | 姿态关键点的“稳定中立—后倾顶点—稳定中立”闭环与模板评分 | 当前最短完整周期为 8 秒；模板须与矢状面特征同口径 |
| 膝关节旋转，且 `KNEE_ROTATION_MODE=bilateral` | 双膝相对位移的双向转动并各自回正；激励型规则分 | 记录的是本段双向完成与回正，不是关节活动度或医疗疗效评级 |
| 膝关节旋转回退/影子模式 | 历史姿态峰值/模板路径或仅诊断 | 不应与双膝规则分混合做趋势比较 |

运行开关会影响**新分析**；历史视频以其 `analysis_version`、`template_version`、`segmentation_version` 和快照解释，不自动重算。三条路径的具体信号、评分边界与回退模式见[三类康复动作拆分分析评分说明](三类康复动作拆分分析评分说明.md)。
