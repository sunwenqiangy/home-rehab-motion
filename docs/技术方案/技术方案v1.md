## 0. 项目背景与技术目标

### 0.1 业务背景

造口旁疝是造口患者出院后最常见的远期并发症之一，多发生于术后 1 年内。规范的腹部肌肉训练（缩腹运动、骨盆倾斜、膝关节旋转）可有效增强腹壁肌力、延缓旁疝发生，但患者在居家场景中缺乏专业反馈，训练质量和依从性难以保障。

本系统以「**患者用手机录制训练视频 → 服务端自动分析动作 → 生成可读报告**」为核心链路，构建一套轻量、可解释、可持续运营的居家康复训练闭环，对应 PRD 所描述的"居家训练动作是否达标、动作哪里存在问题、患者是否持续训练"三大核心问题。

> 完整产品背景与用户角色定义见：《自助式腹部肌肉训练系统产品设计方案 V1.0》§1-§2。

---

### 0.2 核心技术挑战

| 挑战 | 描述 | 本方案应对策略 |
|------|------|---------------|
| **无传感器采集** | 患者仅凭手机摄像头录制，无法使用 IMU、运动捕捉等高精度设备 | 采用 MediaPipe Pose（2D 姿态估计）提取关键点，并建立标准化拍摄角度规范（§6.14）降低误差 |
| **金标准数据极少** | 初期仅有一段教学视频，样本量不足以构建统计可靠的标准动作模型 | 以 mean±σ 模板比对为基础，结合「放宽阈值 + 专家标注 + 患者自报量表」三阶段校准策略（§6.11） |
| **无 GPU 资源** | 部署环境无 GPU，无法使用重型深度学习模型实时推理 | 采用 10fps 降采样 + MediaPipe CPU 版，单次分析目标 < 2 分钟（§6.2） |
| **动作信号退化** | 2D 投影导致不同动作在不同拍摄角度下信噪比差异极大 | 针对三类动作分别选择最优驱动信号（缩腹→躯干角度、骨盆→髋连线角度、膝旋转→双膝中点 X 偏移），并制定单镜头推荐方案（§6.13-§6.14） |
| **分析结果可信度** | 没有外部"真值"参照，无法定量验证分析准确率 | 引入三层独立置信度模型（VQS/KCS/PRS），低置信时降级输出，不强行给出结论性评分（§6.12） |
| **用户依从性** | 患者为术后康复人群，操作能力有限，负面反馈会快速导致流失 | 患者端仅展示可读信息，评级友好（优秀/合格/需改进），初期阈值宽松以降低假阳性率 |

### 0.3 技术目标（第一期）

| 目标维度 | 具体指标 |
|----------|---------|
| **功能完整性** | 覆盖三类动作（缩腹运动、骨盆倾斜、膝关节旋转）的视频上传→分析→报告全链路 |
| **分析性能** | CPU 环境下单次视频分析 ≤ 2 分钟（300s 视频，10fps 采样） |
| **分析可用率** | 高质量视频（VQS≥0.75）分析成功率 ≥ 90%；低质量视频返回明确的拒绝原因 |
| **结果可追溯** | 每次分析结果携带：算法版本号 + 金标准模板版本号 + 三层置信度分数 + 原始参数值 |
| **阈值可维护** | 所有评价参数阈值存库，管理端可可视化调整，修改后新版本即时生效 |
| **数据可沉淀** | 关键点时序数据、分析参数、评分结果全量结构化存储，为第二期监督学习准备 |

### 0.4 第二期技术演进方向

| 演进项 | 方向 |
|--------|------|
| 金标准精化 | 收集 ≥ 100 条有标注患者视频，基于 ROC 曲线重新校准所有阈值 |
| 模型升级 | 引入监督学习分类模型（合格/不合格），替代纯规则引擎 |
| 传感器补充 | 探索 IMU 辅助采集方案（手机陀螺仪），提升骨盆倾斜角度测量精度 |
| 个体化基线 | 为每位患者建立个人历史基线，评价相对进步而非绝对标准 |
| 实时反馈 | 探索视频流实时姿态提示（前端 MediaPipe Web），降低事后纠错成本 |

### 1.1 技术选型总览

| 层级 | 模块 | 技术选型 | 选型理由 |
|------|------|----------|----------|
| 应用层 | 微信小程序 | 微信原生小程序（TypeScript + WXML/WXSS） | 覆盖率最广，原生摄像头/视频 API 完整，官方生态稳定 |
| 应用层 | Web 管理端 | Vue 3 + TypeScript + Element Plus | 开发效率高，生态成熟，适合中后台管理系统 |

| 服务层 | 动作分析服务 | Python FastAPI + MediaPipe / MMPose | Python AI 生态最丰富，FastAPI 高性能异步，易接入姿态估计模型 |
| 服务层 | 异步任务 | Celery + Redis | 视频分析异步解耦，支持重试与优先级调度 |
| 服务层 | 视频处理 | FFmpeg | 成熟稳定，支持转码裁剪，开源可控 |
| 数据层 | 主数据库 | MySQL 8.0 | 事务支持强，运维成本低，关系型业务数据首选 |
| 数据层 | 关键点/JSON 数据 | MySQL JSON 列（初期）→ 可迁移 PostgreSQL JSONB | 初期数据量有限，JSON 列够用；增长后可切 PG 或列存储 |
| 数据层 | 缓存与队列 | Redis 7 | 分析任务状态、频率限制、轮询缓存 |
| 数据层 | 对象存储 | 阿里云 OSS（或私有化 MinIO） | 视频大文件存储，CDN 加速播放 |

### 1.3 核心设计原则

1. **异步分析**：视频上传与动作分析完全解耦，通过消息队列（Celery）异步处理，避免 HTTP 超时，客户端通过轮询获取状态；
2. **可解释优先**：第一期以规则引擎 + 金标准模板比对为主，每条建议可追溯到参数触发条件，不使用黑盒模型自由决策；
3. **置信度保护**：关键点整体置信度低时，不强行输出高确定性评分；质量不足时明确提示用户重新拍摄；
4. **CPU-Only 优化**：暂无 GPU 环境，通过降采样（10fps 提取关键点）+ MediaPipe CPU 版控制单视频分析时间在 2 分钟以内；
5. **版本化模型**：所有标准动作模板、评分阈值、建议模板均携带版本号，每次评价结果记录对应版本，支持历史追溯；
6. **阈值可配置**：所有参数阈值存储在数据库而非代码中，管理端提供阈值调整界面，修改即时生效并自动记录版本；
7. **最小化权限**：患者只能访问本人数据，视频通过带签名的临时 URL 访问（1 小时有效期），管理端按角色隔离。

#### P07 训练报告详情页

**路由**：`/pages/report/detail?video_id=xxx`  
**布局**：纵向滚动，分区展示  
**核心原则**：报告页根据训练阶段动态切换“纠错 / 巩固 / 激励”主视角，而非永远只展示问题反馈。

##### 三阶段判断逻辑

| 阶段 | 判断条件 | 展示主视角 |
|------|----------|-----------|
| **A：纠错期** | 新手（<5次训练）/ 本次评级“需改进”或“无效” / 置信度低 | 纠正问题、改进建议 |
| **B：巩固期** | 连续2-3次“合格” / 评级“合格”但某维度偏低 | 巩固进步、轻微优化 |
| **C：激励期** | 连续3次以上“合格”或“优秀” | 成就激励、持续坚持 |

> 一期先按以上规则执行；同时需支持后台参数化配置（如新手阈值、连续达标次数、时间窗口），由管理端保存版本并生效于新报告。

##### 通用区域（三阶段共享）

| 区域 | 模块名 | 内容描述 | 交互行为 |
|------|--------|----------|----------|
| 顶部 | 报告头部 | 动作类型 + 训练日期 + 置信度标签（高/中/低） | — |
| A 区 | 综合评价卡片 | 大号总分（0-100）+ 大号彩色圆形徽章（80×80dp，含评级文字+表情），颜色：绿/蓝/橙/红 | — |
| B 区 | 完成情况概览 | 有效次数 / 平均保持时间 / 整体稳定性 / 与上次对比（若有历史数据） | — |
| C 区 | 四维评分 | 雷达图（ECharts）+ 纯文字摘要区（如“最需改进：稳定性”），不依赖图表理解 | — |
| 底部 | 操作栏 | 「再练一次」（主按钮满宽）+ 「返回首页」 | 「再练一次」→ P05 |

### 2.4 视频采集与上传流程

```
用户进入录制页
    │
    ▼
展示拍摄要求弹窗（角度/光线/身体入镜范围）
    │
    ▼
选择「立即录制」或「上传本地视频」
    ├── 立即录制 → wx.createCameraContext 录制，完成后得到临时文件路径
    └── 上传本地 → wx.chooseVideo 选择本地文件
    │
    ▼
前端预校验
    • 格式：mp4 / mov
    • 大小：≤ 200MB
    • 时长：10 秒 ~ 300 秒
    │
    ▼
1. 调用 GET /api/v1/videos/presign-upload → 获取 OSS 预签名 URL + video_id
2. wx.uploadFile 直传至 OSS
3. 调用 POST /api/v1/videos/confirm-upload { video_id, action_type, duration }
    │
    ▼
跳转「分析中」页，携带 video_id
    │
    ▼
每 3 秒轮询 GET /api/v1/videos/{video_id}/status
    ├── analyzing    → 展示"分析中..."动效
    ├── completed    → 跳转结果报告页
    ├── failed       → 展示失败原因，提供「重新上传」入口
    └── quality_insufficient → 提示重新按要求拍摄
```

1. **存储结构**：每个动作类型（缩腹/骨盆倾斜/膝关节旋转）各一份阈值配置，存入 `standard_action_template.threshold_config` JSON 列；

## 4. 服务端技术方案

### 4.1 服务拆分说明

| 服务名 | 技术栈 | 核心职责 |
|--------|--------|----------|
| **main-service** | NestJS（Node.js + TypeScript） | 用户认证、业务 CRUD、视频任务调度、消息投递、轮询接口 |
| **analysis-service** | Python FastAPI + Celery Worker | 视频质量检测、关键点提取、参数计算、模板比对、评分生成 |

两个服务独立部署，通过内部 HTTP 接口或消息队列（Redis/RabbitMQ）通信，便于独立扩缩容和版本发布。

### 4.2 用户认证设计

#### 微信小程序登录流程（纯微信一键授权，不绑定手机号）

```
小程序             后端 main-service         微信服务器
   │                     │                      │
   │  wx.login() → code  │                      │
   │──────────────────>  │                      │
   │                     │  GET jscode2session  │
   │                     │──────────────────>  │
   │                     │  openid + session_key│
   │                     │<──────────────────  │
   │                     │                      │
   │                     │ 查找或自动创建 user   │
   │                     │ （仅 openid，无需手机号│
   │                     │  或其他授权）         │
   │                     │ 生成 JWT             │
   │  JWT（含 user_id）   │                      │
   │<──────────────────  │                      │
```

> **设计决策**：患者无需填写注册信息，wx.login 即可完成登录。患者姓名、年龄等基础信息可在首页「个人信息」中选填，或由护士长在管理端补充录入。

- JWT Payload：`{ user_id, role, openid, exp }`
- 有效期：小程序端 30 天（可刷新），管理端 8 小时
- 每个敏感接口（视频/报告）额外校验数据归属（`video.user_id == token.user_id`）

#### 管理端登录

- 账号密码登录，密码使用 bcrypt（cost=12）存储
- 登录成功返回 JWT，含角色信息（nurse / admin）
- 管理端路由和接口均按角色过滤

### 6.5 三类动作参数计算

#### 6.5.1 缩腹运动（abdominal_drawdown）

| 参数 | 计算方法 | 评价意义 | 是否 proxy |
|------|----------|----------|------------|
| `abdominal_displacement` | shoulder_mid 与 hip_mid 连线中点在矢状面方向的相对后移量（归一化到体宽） | 是否真正完成腹部向内收缩 | ✅ proxy |
| `trunk_angle_delta` | trunk_vec 与初始帧 trunk_vec 的夹角 | 是否通过抬起躯干代偿 | 否 |
| `pelvis_shift` | hip_mid 在水平面（XY）的位移（归一化） | 骨盆是否保持稳定 | 否 |
| `hold_duration` | 达到有效收缩阈值后的连续帧数 × 帧间隔（秒） | 训练充分性 | 否 |
| `movement_smoothness` | SPARC（谱弧长）或 jerk（加速度变化率）指标 | 动作控制能力 | 否 |

**合格判定**：`abdominal_displacement` 在金标准有效区间内，且 `trunk_angle_delta < 5°`，`pelvis_shift < 阈值`，`hold_duration ≥ 最低要求`。

#### 6.5.2 骨盆倾斜（pelvic_tilt）

| 参数 | 计算方法 | 说明 |
|------|----------|------|
| `pelvic_tilt_angle` | 基于 LEFT_HIP / RIGHT_HIP 中点构建骨盆向量，与水平面夹角（proxy 方法，真实三维需 PSIS 标记点） | 骨盆前/后倾角度 |
| `pelvic_tilt_delta` | `α_current - α_initial` | 相对初始姿势的倾斜变化量 |
| `pelvis_horizontal_shift` | hip_mid 在水平面的横向位移 | 骨盆是否左右平移 |
| `trunk_angle_delta` | 躯干向量与初始帧夹角 | 躯干代偿检测 |
| `hold_duration` | 目标角度区间内的持续时间 | 保持能力 |

**proxy 说明**：标准三维计算需要 LASIS / RASIS / LPSIS / RPSIS 四个 marker，视频方案用双髋关节中点近似，精度下降，报告中须注明。

#### 6.5.3 膝关节旋转（knee_rotation）

> ⚠️ **方案变更说明（V1.1 → V1.2）**：原方案以股骨-胫骨夹角（髋-膝-踝三点 arccos）作为旋转幅度估计，正面拍摄时两个关键点几乎重叠于同一像素列，夹角估计误差可达 30°+ 且方向信号缺失。新方案改用**双膝中点 X 轴横向偏移**作为主要信号，在正面拍摄下信噪比最佳，可清晰区分左倾/右倾，并通过左右幅度比值直接量化对称性。

| 参数 | 计算方法 | 评价方向 | 说明 |
|------|----------|----------|------|
| `knee_rotation_angle` | `max(|knee_mid_x - knee_mid_x_init|) × 100`（归一化坐标 → %） | **越大越好** | 双膝中点 X 轴偏移幅度，反映倾倒充分性；正面拍摄信噪比优于三点夹角法 |
| `knee_symmetry` | `min(left_amp, right_amp) / max(left_amp, right_amp)`，其中 left_amp/right_amp 为左倾/右倾最大幅度（%） | **越接近 1.0 越好** | 左右倾倒幅度比值，1.0 表示完全对称；比值低说明单侧代偿 |
| `trunk_angle_change` | 躯干向量（肩中→髋中）与初始帧夹角的最大变化量（°） | **越小越好** | 旋转过程中躯干角度代偿量，越小说明核心稳定性越强 |

**合格判定**：`knee_rotation_angle` 在金标准有效区间内，`knee_symmetry ≥ 0.7`，且 `trunk_angle_change < 阈值`。

**拍摄要求**：正面拍摄，摄像头与患者正面平行，髋部以下全部入镜；侧面拍摄时 X 轴信号退化，本方案不适用。

**proxy 说明**：双膝中点 X 轴偏移为 2D 投影，不等同于三维旋转角；受拍摄距离、身体遮挡影响，报告中须注明

    对每个参数与金标准统计值进行比对，输出偏差等级

        (75,  89, "合格"),
        (60,  74, "需改进"),
        (0,   59, "无效"),
    ]

    # 标签 → 分数映射（线性插值）
    LABEL_SCORE_MAP = {
        "normal":  lambda sigma: max(85, 100 - sigma * 5),
        "warning": lambda sigma: max(60, 80 - sigma * 10),
        "invalid": lambda sigma: max(0,  50 - sigma * 10),

    def aggregate_video_score(self, rep_scores: List[RepScore]) -> VideoScore:

#### 6.9.2 教学视频预分析脚本

```python
# scripts/build_gold_standard.py
"""
从教学视频构建金标准模板的独立脚本。
运行方式：python -m scripts.build_gold_standard \
    --video /path/to/教学视频.mp4 \
    --action-type abdominal_crunch \
    --output-dir ./templates/
"""
import json
import numpy as np
from core.pose_estimator import PoseEstimator
from core.data_preprocessor import DataPreprocessor
from core.phase_segmenter import PhaseSegmenter
from core.proxy_metrics import ProxyMetricCalculator

def build_template(video_path: str, action_type: str):
    # Step 1: 与患者视频走同一套提取流水线
    estimator = PoseEstimator()
    raw_frames = estimator.extract_frames(video_path, sample_fps=10)

    # Step 2: 预处理 + 切分
    preprocessor = DataPreprocessor()
    frames = preprocessor.process(raw_frames)
    segmenter = PhaseSegmenter(action_type=action_type)
    phases = segmenter.segment(frames)

    # Step 2.1: 质量校验
    avg_conf = np.mean([f['avg_confidence'] for f in frames])
    missing_rate = np.mean([f['missing_keypoints'] for f in frames]) / 33
    if avg_conf < 0.85 or missing_rate > 0.05:
        print(f"⚠️ 质量不足: avg_conf={avg_conf:.3f}, missing_rate={missing_rate:.3f}")
        print("   建议：人工标注关键点或补拍教学视频")

    # Step 3: 计算各周期参数并统计建模
    calculator = ProxyMetricCalculator(action_type=action_type)
    cycle_params = []
    for phase in phases:
        if phase['phase'] == 'contraction':
            params = calculator.calculate(frames[phase['start']:phase['end']])
            cycle_params.append(params)

    # 统计建模：均值、标准差、百分位
    template_params = {}
    for key in cycle_params[0].keys():
        values = [c[key] for c in cycle_params]
        template_params[key] = {
            "mean": float(np.mean(values)),
            "std": float(np.std(values)),
            "min": float(np.min(values)),
            "max": float(np.max(values)),
            "p5": float(np.percentile(values, 5)),
            "p95": float(np.percentile(values, 95)),
            "n_cycles": len(values)
        }

    # 生成初始阈值配置（基于 ±1.5σ 规则）
    threshold_config = generate_default_thresholds(template_params, action_type)

    # 输出 JSON 模板
    template = {
        "action_type": action_type,
        "source_type": "video",
        "template_params": template_params,
        "threshold_config": threshold_config,
        "quality_report": {
            "avg_confidence": float(avg_conf),
            "missing_rate": float(missing_rate),
            "total_frames": len(frames),
            "valid_cycles": len(cycle_params)
        }
    }
    return template


def generate_default_thresholds(params: dict, action_type: str) -> dict:
    """基于金标准统计量生成默认阈值配置"""
    thresholds = {
        "confidence_min": 0.6,
        "sigma_multiplier": 1.5  # 默认 ±1.5σ
    }

    # 为每个参数生成 valid_range 和 warning_range
    param_threshold_map = {
        "abdominal_crunch": [
            "abdominal_displacement", "displacement_velocity",
            "hold_duration", "trunk_angle_change"
        ],
        "pelvic_tilt": [
            "pelvic_tilt_delta", "pelvis_shift",
            "hold_duration", "trunk_angle_change"
        ],
        "knee_rotation": [
            "knee_rotation_angle", "rotation_velocity",
            "hold_duration", "pelvis_shift"
        ]
    }

    for param_name in param_threshold_map.get(action_type, []):
        if param_name not in params:
            continue
        p = params[param_name]
        sigma_mult = thresholds["sigma_multiplier"]
        thresholds[param_name] = {
            "valid_range": [p["mean"] - sigma_mult * p["std"],
                           p["mean"] + sigma_mult * p["std"]],
            "warning_range": [p["mean"] - 2.5 * p["std"],
                             p["mean"] + 2.5 * p["std"]],
            "gold_mean": p["mean"],
            "gold_std": p["std"]
        }

    return thresholds
```

### 6.10 金标准方案优缺点深度分析（V1.3 新增）

> 本节内容来自《动作分析技术方案详解 V1.0 §1-§2》。

#### 6.10.1 现有方案核心假设

| 假设 | 描述 | 风险评分 |
|------|------|--------|
| 视频代表性 | 教学视频中的动作是"标准"的，可代表目标用户应完成的动作规范 | ⚠️ 高风险：示范员健康体能 ≠ 造口患者；**金标准下限必须由康复医生临床定义，不能纯靠统计推断** |
| 周期可分离 | 教学视频包含多个可重复的独立训练周期，可用于统计建模 | ✅ 可行，小样本下需放宽 σ 倍数并标注不确定性 |
| 2D 足够 | MediaPipe 的 2D 投影坐标可替代 3D 运动捕捉数据用于评价 | ⚠️ 中风险：单角度拍摄误差可达 15°+，需标准化拍摄角度（见 §6.14） |
| 缩腹代理有效 | **已修正**：腹壁收缩为横向动作，改用躯干稳定性（trunk_stability）+ 髋宽变化率（abdominal_contraction_ratio）作为代理指标；原「肩-髋中点 Y 轴位移」仅反映躯干前屈代偿，已移除 | ✅ 已修复 |

#### 6.10.2 优点

| 优点 | 说明 | 重要程度 |
|------|------|----------|
| **零门槛启动** | 无需额外数据采集，仅需一段视频即可建立初始模板，可在项目启动当天完成 | ⭐⭐⭐⭐⭐ |
| **工具链统一** | 患者视频与教学视频走完全相同的分析管线，避免系统性差异 | ⭐⭐⭐⭐⭐ |
| **可解释性强** | 所有阈值均可追溯到原始统计量（mean±1.5σ），专家可直接审核和调整 | ⭐⭐⭐⭐ |
| **版本可控** | 阈值存库、专家可微调、每次修改生成新版本，完全可追溯 | ⭐⭐⭐⭐ |
| **CPU 友好** | 10fps 降采样 + MediaPipe CPU 版，无 GPU 环境下单次分析 < 2 分钟 | ⭐⭐⭐⭐ |
| **可迭代** | 积累患者数据后可逐步收紧阈值，路径清晰 | ⭐⭐⭐ |

#### 6.10.3 缺点与风险

**缺点 1：样本量极小（n=1 视频，n_cycles 极少）**

单段教学视频通常包含 5~15 个训练周期，基于如此少的样本计算 std 在统计上极不可靠：
- 若教学视频中动作较快，std 极小 → 假阳性率高
- 若存在 1~2 个"起始慢"的周期，std 偏大 → 假阴性率高

```
n_cycles = 8 时，std 估计的置信区间约为真实 std 的 [0.67, 1.71] 倍
（95% CI，基于卡方分布）
换言之：若真实 std=2°，观测 std 可能为 1.3°~3.4°，阈值误差极大
```

**缺点 2：教学视频执行者不代表所有患者群体**

- 教学视频由健康治疗师/示范员完成，动作流畅、幅度大
- 造口患者（术后 1 年内）肌力弱，动作幅度可能仅为示范者的 50-70%
- 高假阳性率 → 患者长期负面反馈 → 依从性下降 → 系统无人使用

**缺点 3：2D 代理指标的系统误差**

| 指标 | 代理方式 | 误差来源 |
|------|----------|----------|
| 骨盆倾斜角 | 双髋连线角度 | 缺少 ASIS/PSIS 真实标记，髋部皮下脂肪影响关键点定位 |
| 膝关节旋转幅度 | 双膝中点 X 轴横向偏移（正面拍摄） | 假设拍摄与患者正面平行，偏转角度大时 X 轴投影缩小 |

**缺点 4：置信度无法独立验证** — 没有外部"真值"参照（无同步传感器数据、无多人标注），无法定量验证报告准确率。

**缺点 5：阶段切分依赖启发式规则，鲁棒性弱** — 对噪声敏感，切分错误会导致参数计算错误，但系统不一定能检测到。

#### 6.10.4 风险等级汇总

| 风险项 | 等级 | 影响范围 | 可缓解性 |
|--------|------|----------|----------|
| 小样本 std 不稳定 | 🔴 高 | 所有评价结果 | 可缓解（初期放宽阈值 + 人工校准） |
| 患者群体代表性偏差 | 🔴 高 | 评分合格率 | 需收集真实患者数据才能根本解决 |
| 2D 代理指标误差 | 🟡 中 | 角度/位移精度 | 部分可缓解（标准化拍摄要求） |
| 置信度无法验证 | 🟡 中 | 系统公信力 | 可通过多方案对比缓解 |
| 阶段切分鲁棒性 | 🟡 中 | 异常视频处理 | 需增加容错与降级策略 |

### 6.11 金标准替代与增强方案（V1.3 新增）

> 本节内容来自《动作分析技术方案详解 V1.0 §3-§6》。

#### 方案 A：放宽初始阈值 + 快速专家校准（立即执行）

**核心思路**：承认当前样本量不足，主动放宽阈值，通过早期真实患者反馈快速校准。

```
Step 1: sigma_multiplier = 2.5（从 1.5σ 放宽至 2.5σ），warning_range 扩大至 4σ

Step 2: 上线后 2 周内招募 5~10 名患者，由治疗师在旁观察记录
        收集「系统判合格 但人工判不合格」和「系统判不合格 但人工判合格」的案例

Step 3: 基于 20~30 条已标注数据，更新阈值 → 版本 v2
```

**优点**：成本最低、最快落地；**缺点**：初期评价精度较低，需人工配合

#### 方案 B：多专家人工标注增强（第一期核心补充）

**核心思路**：邀请 2~3 名物理治疗师/护士长对教学视频每个周期进行人工参数标注。

```
流程：
  视频播放 + 逐帧暂停 → 专家标注每个周期是否标准（Y/N）
      │
  ICC（组内相关系数）计算
      如 ICC ≥ 0.75 → 标注可信 → 用标注均值更新 gold_mean
      如 ICC < 0.75 → 重新讨论标准 → 再标注
```

**工具建议**：使用 Label Studio（开源）+ 视频帧截图标注功能  
**优点**：直接引入临床经验，ICC 可量化标注质量  
**缺点**：需要治疗师投入 2-4 小时，需要标注工具搭建

#### 方案 C：多角度视频采集建立 3D 代理基准（第一期可选）

用 2 个摄像头同时录制标准动作（侧面 90° + 正面 0°），利用多视角提升关键点精度：
- 摄像头 1：侧面 90°（缩腹信号最佳）
- 摄像头 2：正面 0°（骨盆倾斜角 + 膝关节旋转信号均最佳）

**优点**：根本上提升 3D 估计精度；**缺点**：患者上传视频仍是单摄像头，多视角仅用于金标准建立

#### 方案 D：IMU 传感器辅助金标准采集（第二期）

在采集教学视频时，同时佩戴惯性传感器（IMU）获取高精度运动数据。

| 设备 | 精度 | 成本 |
|------|------|------|
| 手机加速度计/陀螺仪 | 中等（约 ±3°） | 免费 |
| LPMS-B2 | 中高（约 ±1-2°） | ¥3-5 千/个 |
| Xsens MTw Awinda | 高（< 1°） | ¥5-20 万套装 |

**最低成本方案**：在腰骶部和胸骨各放置一部手机（用 Phyphox App 录制加速度计数据），与视频时间戳对齐，提取骨盆倾斜角和躯干角度真值。

#### 方案 E：患者自报量表辅助验证（第一期推荐，零成本）

训练结束后在小程序弹出 2 道简短问题（≤ 30 秒完成）：

```
Q1: 本次训练中，您感觉腹部收紧的程度是？
    [没有感觉] [轻微感觉] [明显感觉到] [非常明显]

Q2: 本次训练，骨盆是否保持了稳定？
    [完全稳定] [轻微晃动] [明显晃动]
```

**用途**：系统评分"优秀"但患者自报"没有感觉" → 可能是假阳性

#### 方案 F：LLM 增强置信度评估（第二期探索）

将关键点数据、参数计算结果、视频质量报告同时输入大模型，生成综合置信度评估和结构化理由。成本约 0.01-0.05 元/次调用；输出不稳定，需人工审核建议库。

### 6.12 分层置信度模型与降级策略（V1.3 新增）

> 本节内容来自《动作分析技术方案详解 V1.0 §5》。

#### 6.12.1 三层独立置信度

```
置信度 = f(视频质量置信度, 关键点置信度, 参数可信度)

视频质量置信度（Video Quality Score, VQS）
├─ 关键区域入镜完整度（身体遮挡比例）
├─ 帧率稳定性（是否有大量丢帧）
├─ 图像清晰度估算（Laplacian 方差）
└─ 拍摄角度合适度（基于躯干中心线与垂直线夹角）

关键点置信度（Keypoint Confidence Score, KCS）
├─ 平均 visibility 分数（MediaPipe 输出）
├─ 关键点缺失率（< 5% 为高置信）
└─ 关键点轨迹平滑度（抖动过多为低置信）

参数可信度（Parameter Reliability Score, PRS）
├─ 阶段切分成功率（切出了预期数量的周期？）
├─ 各参数是否在物理合理范围内（骨盆位移 > 10cm 不可信）
└─ 参数内部一致性（腹部收缩时速度是否合理？）
```

**综合置信度计算**：

```
Confidence = 0.4 × VQS + 0.35 × KCS + 0.25 × PRS

高置信度: ≥ 0.75 → 正常出报告
中置信度: 0.55-0.74 → 出报告 + 黄色提示「部分结果仅供参考」
低置信度: < 0.55 → 不出结论性报告 → 强烈建议重新录制

⚠️ 注意：上述阈值（0.75 / 0.55）为初始经验值，尚未基于真实患者数据验证。
需在第二阶段（收集 ≥ 50 条已标注视频）后通过 ROC 曲线重新校准。
```

#### 6.12.2 降级策略

当置信度不足时，系统应降级输出而非硬性判断：

| 置信度级别 | 降级输出策略 |
|------------|-------------|
| 高（≥0.75） | 输出完整报告：总分 + 四维评分 + 建议 |
| 中（0.55-0.74） | 输出简化报告：总分 + 主要问题（1 条）+ 「本次分析仅供参考」 |
| 低（<0.55） | 不输出结论性分数：仅提示「视频质量不足，无法完成分析」+ 改善拍摄建议 |
| 质量检测不通过 | 视频上传时拦截：直接拒绝分析，返回具体质量问题 |

#### 6.12.3 关键点质量增强策略

```python
class KeypointQualityEnhancer:
    def enhance(self, frames: list) -> list:
        frames = self._fill_missing_by_interpolation(frames)  # 线性插值填充缺失帧（最多连续 5 帧）
        frames = self._smooth_by_savgol(frames, window=5)     # Savitzky-Golay 平滑
        frames = self._reject_physically_impossible(frames)   # 过滤物理不合理值
        frames = self._normalize_to_subject_height(frames)    # 按人体高度归一化（肩-髋距离作参考尺度）
        return frames
```

### 6.13 有效周期计算机制详解（V1.3 新增）

> 本节内容来自《动作分析技术方案详解 V1.0 §8》。

有效周期（Valid Cycle）是参数统计建模的最小单元，指一次完整的「收缩 → 保持 → 回正」往返过程。整个检测分为四步。

#### 6.13.1 选择驱动信号

不同动作用不同的物理量来代表波峰/波谷，每帧均从 MediaPipe 关键点实时计算：

| 动作 | 切分驱动信号 | 计算公式 | 极值方向 | 备注 |
|------|------------|---------|----------|------|
| **缩腹运动** | 躯干角度（肩中-髋中连线与垂直轴夹角） | `degrees(arctan2(肩中X - 髋中X, -(肩中Y - 髋中Y)))` | 找极大值 | 与参数计算信号完全分离，避免选择偏差 |
| **骨盆倾斜** | 双髋连线角度 | `degrees(arctan2(右髋Y - 左髋Y, 右髋X - 左髋X))` | 找极大值（倾斜顶峰角度最大） | — |
| **膝关节旋转** | 双膝中点 X 轴横向偏移 | `(L_knee_x + R_knee_x) / 2`，找偏移极大值 | 找极大值（双膝向右倾倒到最大位移时 X 增大） | 正面拍摄，原三点夹角法在正面信号退化 |

#### 6.13.2 移动平均平滑

```python
win = min(5, max(2, len(signal) // 15))   # 窗口大小约为总帧数的 1/15
smoothed = np.convolve(signal, np.ones(win)/win, mode="same")
```

MediaPipe 逐帧输出存在抖动噪声，平滑后波峰形状更稳定，防止把体位微晃动误识别为一次完整动作。

#### 6.13.3 用 `scipy.find_peaks` 检测极值点

```python
centered = smoothed - np.mean(smoothed)    # 去均值，消除全局偏移
min_dist = max(3, int(SAMPLE_FPS * 1.5))   # 相邻两峰最短间距 = 1.5 秒

# 缩腹、骨盆倾斜：直接找极大值
peaks = find_peaks(centered, distance=min_dist, prominence=0.003)

# 膝关节旋转：双膝中点X轴横向偏移，直接找极大值（prominence 提至 0.01 过滤噪声）
peaks = find_peaks(centered, distance=min_dist, prominence=0.01)
```

| 参数 | 值 | 作用 |
|------|----|------|
| `distance` | ≥ 1.5s 对应帧数 | 同一次动作不被切成两个峰 |
| `prominence` | 0.003（归一化坐标） | 过滤背景噪声造成的微小假峰 |

#### 6.13.4 以相邻峰为边界切周期

```python
for i, peak in enumerate(peaks):
    st = peaks[i-1] if i > 0 else max(0, peak - SAMPLE_FPS*3)     # 起点 = 上一个峰
    en = peaks[i+1] if i < len(peaks)-1 else min(last_frame, peak + SAMPLE_FPS*3)  # 终点 = 下一个峰
    dur = timestamps[en] - timestamps[st]
    if dur < 1.5:    # 过滤太短的伪周期
        continue
    cycles.append({ "start_frame": st, "end_frame": en })
```

示意图（以 4 个极值点为例）：

```
信号波形：  ∧     ∧     ∧     ∧
           / \   / \   / \   / \
          /   \ /   \ /   \ /   \
              P1    P2    P3    P4   ← 4 个极值点

切分边界：
  |──P1──|──P2──|──P3──|──P4──|
  周期1   周期2   周期3   周期4
```

#### 6.13.5 有效性判断三条件

| 判断条件 | 参数来源 | 说明 |
|---------|---------|------|
| 信号突出度 ≥ 0.003 | `prominence` | 排除背景噪声造成的假峰 |
| 周期时长 ≥ 1.5 秒 | `dur < 1.5 → skip` | 排除动作太快、不完整的片段 |
| 相邻峰间距 ≥ 1.5 秒 | `distance` | 同一次动作不重复计数 |

只有同时通过三条件的周期才进入后续参数计算和统计建模。

### 6.14 单镜头最佳拍摄角度规范（V1.3 新增）

> 本节内容来自《动作分析技术方案详解 V1.0 §9》。

#### 6.14.1 核心问题

MediaPipe Pose 基于 **2D 图像** 推断姿态，摄像头角度直接决定哪些关键点可见、哪些代理指标可靠。

#### 6.14.2 各动作最优角度

| 动作 | 最优角度 | 原因 |
|------|---------|------|
| **缩腹运动** | 正侧面（90° 侧拍） | 躯干前屈在侧面视角的 Y 轴变化最大；正面拍摄时 Y 轴变化几乎为零，极值检测完全失效 |
| **骨盆倾斜** | 正面（0° 正拍） | 双髋的 X 坐标间距最大，角度变化最灵敏；侧面拍摄时双髋几乎重叠，arctan2 数值跳动剧烈不可用 |
| **膝关节旋转** | 正面 0°（V1.2 方案变更） | 双膝左右偏移在 X 坐标变化最大，信噪比最高；侧面信号退化为噪声 |

#### 6.14.3 综合推荐（单镜头只能选一个）

| 角度 | 缩腹 | 骨盆倾斜 | 膝关节旋转 | 综合评分 |
|------|------|---------|----------|----------|
| **正面 0°** | ❌ 差 | ✅ 最好 | ✅ 最好（V1.2） | ⭐⭐⭐ |
| **侧面 90°** | ✅ 最好 | 🟡 一般 | ❌ 不可用（V1.2） | ⭐⭐ |
| 斜前方 45° | 🟡 一般 | 🟡 一般 | 🟡 次选（V1.2） | ⭐⭐⭐ |
| 斜后方 135° | ❌ 差 | 🟡 一般 | ❌ 差 | ⭐ |

> **V1.2 推荐策略变更**：膝关节旋转方案改为双膝中点 X 轴横向偏移后，**正面拍摄**同时入选骨盆倾斜 + 膝关节旋转，成为单镜头最优解。缩腹训练仍推荐侧面拍摄，如同时涉及多种动作建议配置两个摄像头或分开预约。

#### 6.14.4 拍摄规范实施细则

| 拍摄要求 | 推荐值 | 关键原因 | 自动检测方式 |
|----------|--------|---------|-------------|
| **拍摄角度** | **侧面 90°**（或斜前方 45°） | 最大化各动作代理信号幅度 | 躯干中心线与垂直线夹角检测 |
| **摄像头高度** | 与患者髋部等高（约 1m） | 减少透视畸变，关键点投影更准确 | 髋点 Y 坐标在画面中位置检测 |
| **拍摄距离** | 2.5 ~ 3 米 | 确保全身（头顶到脚踝）入画 | MediaPipe 全身关键点置信度 |
| **背景** | 纯色、无杂乱物体 | 提升 MediaPipe 前景分割置信度 | 背景复杂度估算 |
| **光线** | 正面补光，不逆光 | 避免轮廓模糊和关键点丢失 | 图像亮度分布检测 |
| **着装** | 贴身运动服 | 宽松衣物遮蔽关节点，置信度骤降 | 提示文字（无法自动检测） |
| **摄像头稳定** | 三脚架/支架固定 | 消除摄像头抖动引入的伪位移 | 帧间背景运动向量 |
| **无他人入镜** | 仅患者本人 | 避免 MediaPipe 识别错误身体 | 人体检测数量 |

> ⚠️ **与当前教学视频的对照**：现有教学视频置信度 0.74、关键点缺失率 29%，大概率源于拍摄角度或遮挡问题。若改为侧面 90° 重新拍摄教学视频后重跑 `extract_gold_standard.py`，切分精度和统计可信度会有明显改善。

### 9.3 MediaPipe 模型部署

```python
# analysis-service/core/pose_estimator.py
import mediapipe as mp
import cv2

class PoseEstimator:
    def __init__(self):
        # 启动时加载模型（避免每次推理重新初始化）
        self.mp_pose = mp.solutions.pose
        self.pose = self.mp_pose.Pose(
            static_image_mode=False,
            model_complexity=1,        # 0=轻量, 1=标准, 2=高精度
            smooth_landmarks=True,
            min_detection_confidence=0.5,
            min_tracking_confidence=0.5
        )

    def extract_frames(self, video_path: str,
                       sample_fps: int = 10) -> List[Frame]:
        """
        从视频中按 sample_fps 采样帧，提取关键点
        sample_fps=10 可将 30fps 视频帧数降至 1/3，减少计算量
        """
        cap = cv2.VideoCapture(video_path)
        source_fps = cap.get(cv2.CAP_PROP_FPS)
        step = max(1, int(source_fps / sample_fps))
        frames = []
        frame_index = 0
        while cap.isOpened():
            ret, frame = cap.read()
            if not ret:
                break
            if frame_index % step == 0:
                results = self.pose.process(
                    cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)
                )
                frames.append(self._parse_result(results, frame_index))
            frame_index += 1
        cap.release()
        return frames
```

## 10. 安全与合规方案

### 10.1 数据安全措施

| 场景 | 措施 |
|------|------|
| 传输安全 | 全链路 HTTPS（TLS 1.2+），小程序通过微信内置 TLS 通道 |
| 视频访问 | OSS 私有 Bucket + 带签名临时 URL（有效期 1 小时），禁止公开直接访问 |
| 用户数据隔离 | 所有视频/报告接口校验 `video.user_id == token.user_id`，患者无法访问他人数据 |
| 管理端权限 | RBAC 角色控制（patient/nurse/admin），接口层逐个校验角色权限 |
| 密码存储 | bcrypt（cost=12）哈希存储，禁止明文 |
| JWT 安全 | RS256 非对称签名（或 HS256 长密钥），敏感操作二次验证 |
| SQL 注入防护 | 使用 ORM（TypeORM / MyBatis）参数化查询，禁止拼接 SQL |

### 10.2 隐私与合规

1. **最小化收集**：患者信息只收集训练必需字段（姓名/年龄/性别），不强制绑定身份证等敏感信息；
2. **视频脱敏**：患者端不展示其他用户视频，指导内容视频中不出现患者个人信息；
3. **访问日志**：所有视频下载/预览操作记录访问日志（user_id、时间、操作类型），保留 180 天；
4. **数据删除**：支持患者申请删除本人视频（逻辑删除 + OSS 异步清理）；
5. **合规声明**：系统评价结果标注"仅供参考，不替代专业医疗诊断"；
6. **服务条款**：小程序首次使用需患者签署知情同意，明确数据用途。

### 10.3 医疗安全声明

所有分析结果和建议须在 UI 中明确标注：

> 本系统评价结果基于视频图像分析，为辅助参考信息，不构成医疗诊断。建议及分析结果须经医护人员审核后参考使用。
