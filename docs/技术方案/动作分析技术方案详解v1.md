## 1. 现有金标准方案：单段教学视频统计建模

### 1.1 方案核心流程

```
教学视频.mp4（唯一参考源）
    │
    ▼  sample_fps=10（CPU 优化）
[MediaPipe Pose] → 逐帧 33 关键点坐标 + 置信度
    │
    ▼
[有效周期检测器（详见第 8 章）]
    每种动作独立使用不同驱动信号：
    ├─ 缩腹：躯干角度周期微变化（切分信号）
    ├─ 骨盆倾斜：双髋连线角度变化
    └─ 膝关节旋转：双膝中点 X 轴横向偏移（正面拍摄，找极大值）
    ⚠️ 切分信号与参数计算信号完全分离，避免选择偏差
    │
    ▼  遍历各有效周期（通过三条有效性判断）
[代理指标计算器 ProxyMetricCalculator]
  缩腹动作：
    ├─ trunk_stability           躯干稳定性（越小越好 ★）
    ├─ trunk_max_deviation       躯干最大偏移角（代偿识别）
    ├─ abdominal_contraction_ratio  髋宽相对变化率（腹围收缩代理）
    ├─ contraction_velocity      收缩速度
    ├─ trunk_angle_change        躯干角度代偿变化量（通用）
    ├─ pelvis_shift              骨盆水平偏移（通用）
    └─ hold_duration             保持时长（通用）
  骨盆倾斜：pelvic_tilt_delta / pelvic_tilt_velocity / hold_duration / 通用
  膝关节旋转：knee_rotation_angle（双膝中点X轴偏移 %）/ knee_symmetry（左右幅度比值）/ trunk_angle_change（躯干稳定性）
    │
    ▼  n 个有效周期 → 统计建模
[统计参数]
    mean / std / min / max / p5 / p95 / n_cycles
    │
    ▼  ±2.0σ 初始规则（属统计上限，下限需康复医生临床定义）
[threshold_config 初始阈值]
    valid_range / warning_range / gold_mean / gold_std
    │
    ▼  康复医生/护士长审核下限阈值 + 专家微调（必需步骤）
[写入数据库] → standard_action_template（version=1）
```

### 1.2 核心假设

| 假设 | 描述 | 风险评分 |
|------|------|--------|
| 视频代表性 | 教学视频中的动作是"标准"的，可代表目标用户应完成的动作规范 | ⚠️ 高风险：示范员健康体能 ≠ 造口患者；**金标准下限必须由康复医生临床定义，不能纯靠统计推断** |
| 周期可分离 | 教学视频包含多个可重复的独立训练周期，可用于统计建模 | ✅ 可行，小样本下需放宽 σ 倍数并标注不确定性 |
| 2D 足够 | MediaPipe 的 2D 投影坐标可替代 3D 运动捕捉数据用于评价 | ⚠️ 中风险：单角度拍摄误差可达 15°+，需标准化拍摄角度（见第 9 章） |
| 缩腹代理有效 | **已修正**：腹壁收缩为横向动作，改用躯干稳定性（trunk_stability）+ 髋宽变化率（abdominal_contraction_ratio）作为代理指标；原「肩-髋中点 Y 轴位移」仅反映躯干前屈代偿，已从缩腹参数中移除 | ✅ 已修复 |

## 2. 优缺点深度分析

### 2.1 优点

| 优点 | 说明 | 重要程度 |
|------|------|----------|
| **零门槛启动** | 无需额外数据采集，仅需一段视频即可建立初始模板，可在项目启动当天完成 | ⭐⭐⭐⭐⭐ |
| **工具链统一** | 患者视频与教学视频走完全相同的分析管线（MediaPipe + 相同预处理），避免系统性差异 | ⭐⭐⭐⭐⭐ |
| **可解释性强** | 所有阈值均可追溯到原始统计量（mean±1.5σ），专家可直接审核和调整 | ⭐⭐⭐⭐ |
| **版本可控** | 阈值存库、专家可微调、每次修改生成新版本，完全可追溯 | ⭐⭐⭐⭐ |
| **CPU 友好** | 10fps 降采样 + MediaPipe CPU 版，无 GPU 环境下单次分析 < 2 分钟 | ⭐⭐⭐⭐ |
| **可迭代** | 积累患者数据后可逐步收紧阈值，路径清晰 | ⭐⭐⭐ |

### 2.2 缺点与风险

#### 缺点 1：样本量极小（n=1 视频，n_cycles 极少）

**问题描述**：

单段教学视频通常包含 5~15 个训练周期，基于如此少的样本计算 std（标准差）在统计上极不可靠。

- 若教学视频中动作较快，所有周期参数密集，std 极小 → 患者稍有偏差就被判"异常"（假阳性率高）
- 若教学视频中存在 1~2 个"起始慢"的周期，std 偏大 → 阈值过宽，真正错误的动作也通过（假阴性率高）
- 正态分布假设在小样本下极不稳定，p5/p95 百分位估算误差可达 30-50%

**量化风险**：

```
n_cycles = 8 时，std 估计的置信区间约为真实 std 的 [0.67, 1.71] 倍
（95% CI，基于卡方分布）
换言之：若真实 std=2°，观测 std 可能为 1.3°~3.4°，阈值误差极大
```

**影响**：初始阈值可能偏紧或偏松，导致大量患者视频被错误判定。

---

#### 缺点 2：教学视频执行者不代表所有患者群体

**问题描述**：  
- 教学视频通常由健康的治疗师或示范员完成，动作流畅、幅度大、保持时间长
- 造口患者（术后 1 年内）肌力弱、运动范围受限，动作幅度可能仅为示范者的 50-70%
- 若金标准来自示范者，有效阈值可能让大多数患者"永远达不到合格"

**影响**：高假阳性率 → 患者长期接到负面反馈 → 依从性下降 → 系统无人使用。

---

#### 缺点 3：2D 代理指标的系统误差

**问题描述**：

| 指标 | 代理方式 | 误差来源 |
|------|----------|----------|
| 腹部收缩位移 | 左右肩中点 Y 坐标变化 | 拍摄角度不同造成透视畸变；驼背患者肩部位置偏移 |
| 骨盆倾斜角 | 双髋连线角度 | 缺少 ASIS/PSIS 真实标记，髋部皮下脂肪影响关键点定位 |
| 膝关节旋转幅度 | 双膝中点 X 轴横向偏移（正面拍摄） | 假设拍摄与患者正面平行，偏转角度大时 X 轴投影缩小；与髋-膝-踝夹角法相比，正面信噪比显著提升 |

教学视频在固定镜头/固定角度下拍摄，患者视频角度千变万化 → 同一动作在不同拍摄角度下代理指标值差异显著。

---

#### 缺点 4：置信度无法独立验证

**问题描述**：  
当前方案基于规则生成报告，但没有外部"真值"参照（无同步传感器数据、无多人标注、无临床量表评分），无法定量验证报告准确率。

**影响**：医护人员对系统输出的信任度难以建立，推广受阻。

---

#### 缺点 5：阶段切分依赖启发式规则，鲁棒性弱

**问题描述**：  
`PhaseSegmenter` 基于关键点速度/位置变化检测阶段边界（如收缩开始/结束时刻），这类启发式方法：
- 对噪声敏感（患者呼吸、身体微晃动均会触发错误边界）
- 对视频质量敏感（光线不足、遮挡直接导致切分失败）
- 对不同动作类型的泛化能力弱（缩腹 vs 骨盆倾斜的切分逻辑完全不同）

**影响**：切分错误 → 参数计算错误 → 评分完全失效，但系统不一定能检测到这个问题。

---

### 2.3 风险等级汇总

| 风险项 | 等级 | 影响范围 | 可缓解性 |
|--------|------|----------|----------|
| 小样本 std 不稳定 | 🔴 高 | 所有评价结果 | 可缓解（初期放宽阈值 + 人工校准） |
| 患者群体代表性偏差 | 🔴 高 | 评分合格率 | 需收集真实患者数据才能根本解决 |
| 2D 代理指标误差 | 🟡 中 | 角度/位移精度 | 部分可缓解（标准化拍摄要求） |
| 置信度无法验证 | 🟡 中 | 系统公信力 | 可通过多方案对比缓解 |
| 阶段切分鲁棒性 | 🟡 中 | 异常视频处理 | 需增加容错与降级策略 |

## 3. 替代与增强方案

### 方案 A：放宽初始阈值 + 快速专家校准（建议立即执行）

**核心思路**：承认当前样本量不足，主动放宽阈值，通过早期真实患者反馈快速校准。

**操作步骤**：

```
Step 1: 构建脚本（已有）
    sigma_multiplier = 2.5  # 从 1.5σ 放宽至 2.5σ
    warning_range 相应扩大至 4σ

Step 2: 早期运营（上线后 2 周内）
    招募 5~10 名患者，同时由治疗师在旁观察（人工记录是否真的合格）
    收集「系统判合格 但人工判不合格」和「系统判不合格 但人工判合格」的案例

Step 3: 校准（2 周后）
    基于 20~30 条已标注数据，更新阈值 → 版本 v2
```

**优点**：成本最低、最快落地  
**缺点**：初期评价精度较低，需人工配合

---

### 方案 B：多专家人工标注增强（推荐第一期核心补充）

**核心思路**：邀请 2~3 名物理治疗师/护士长对教学视频每个周期进行人工参数标注，用标注值代替纯统计值。

**操作流程**：

```
┌─────────────────────────────────────┐
│  专家标注工具（轻量 Web 界面）         │
│  ┌──────────────────────────────┐   │
│  │  视频播放 + 逐帧暂停          │   │
│  │  标注项：                    │   │
│  │  • 收缩开始帧 / 结束帧       │   │
│  │  • 该周期是否标准？（Y/N）    │   │
│  │  • 腹部收缩幅度（主观评估）  │   │
│  │  • 骨盆稳定性（1-5 分）      │   │
│  │  • 备注                      │   │
│  └──────────────────────────────┘   │
└─────────────────────────────────────┘
    │
    ▼
ICC（组内相关系数）计算  →  评估者间信度
    如 ICC ≥ 0.75 → 标注可信 → 用标注均值更新 gold_mean
    如 ICC < 0.75 → 重新讨论标准 → 再标注
```

**工具建议**：使用 Label Studio（开源）+ 视频帧截图标注功能

**优点**：
- 直接引入临床经验，避免纯统计的局限
- ICC 可量化标注质量，报告可引用

**缺点**：需要治疗师投入 2-4 小时，需要标注工具搭建

---

### 方案 C：多角度视频采集建立 3D 代理基准

**核心思路**：对同一段标准动作用 2-3 个摄像头同时录制，利用多视角信息提升关键点精度。

```
摄像头设置（建议初期最低配置，角度选择依据详见第 9 章）：
  摄像头 1：侧面 90°（缩腹信号最佳）
  摄像头 2：正面 0°（骨盆倾斜角 + 膝关节旋转信号均最佳）

多视角融合：
  同时送入 MediaPipe → 分别提取关键点
  利用已知摄像头位置关系进行三角定位
  → 提升骨盆倾斜角、膝旋转角的估计精度
```

**成本预估**：
- 设备：一部额外手机（已有）
- 人工：录制 30 分钟标准视频 × 1 次
- 开发：多视角融合算法约 1 周开发量

**优点**：根本上提升 3D 估计精度，特别是骨盆倾斜角  
**缺点**：患者上传视频仍是单摄像头，多视角仅用于金标准建立；实现复杂度较高

---

### 方案 D：IMU 传感器辅助金标准采集（高精度，推荐第二期）

**核心思路**：在采集教学视频金标准时，同时佩戴惯性传感器（IMU）获取高精度运动数据。

**设备选项**：

| 设备 | 精度 | 成本 | 数据格式 |
|------|------|------|----------|
| 手机加速度计/陀螺仪 | 中等（约 ±3°） | 免费 | JSON/CSV |
| Xsens MTw Awinda | 高（< 1°） | ¥5-20 万套装 | BVH/CSV |
| LPMS-B2 | 中高（约 ±1-2°） | ¥3-5 千/个 | CSV |
| Movella DOTS（Xsens）| 高（< 1°） | ¥8-15 万套装 | CSV |
| 手机 + PhysiTrack App | 中（约 ±5°） | 极低 | 导出 CSV |

**最低成本方案（推荐验证用）**：  
在腰骶部和胸骨放置 2 个手机（用 Phyphox App 录制加速度计数据），与视频时间戳对齐，提取骨盆倾斜角和躯干角度真值。

**优点**：高精度"真值"参照，可验证 2D 代理指标的误差范围  
**缺点**：需要额外设备和数据同步工作

---

### 方案 E：患者自报量表辅助验证（低成本可信度增强）

**核心思路**：每次训练后让患者在小程序填写 2 道题，将主观感受与系统评分交叉验证。

```
训练结束后弹出简短量表（≤ 30 秒完成）：

Q1: 本次训练中，您感觉腹部收紧的程度是？
    [没有感觉] [轻微感觉] [明显感觉到] [非常明显]

Q2: 本次训练，骨盆是否保持了稳定？
    [完全稳定] [轻微晃动] [明显晃动]
```

**用途**：
- 系统评分"优秀"但患者自报"没有感觉" → 可能是假阳性
- 系统评分"无效"但患者自报"非常明显" → 可能是视频质量问题

**优点**：几乎零成本，可立即集成  
**缺点**：患者自报存在主观偏差，仅作辅助参考

---

### 方案 F：LLM 增强的置信度评估（探索性，第二期）

**核心思路**：将关键点数据、参数计算结果、视频质量报告同时输入大模型，生成综合置信度评估和结构化理由。

```python
# 伪代码示意
prompt = f"""
你是一个运动康复分析专家。以下是患者缩腹训练的分析数据：

关键点质量：avg_confidence={avg_conf:.2f}, missing_rate={missing_rate:.1%}
视频质量：帧率={fps}fps, 分辨率={resolution}
分析参数：
  - 腹部收缩位移: {displacement:.1f}cm（参考值: {gold_mean:.1f}±{gold_std:.1f}cm）
  - 骨盆偏移: {pelvis_shift:.1f}cm（参考值: <{threshold:.1f}cm）
  - 保持时长: {hold_duration:.1f}s（目标: ≥{target_duration:.1f}s）

请评估：
1. 本次分析的置信度（高/中/低）及理由
2. 识别出的代偿动作类型
3. 给患者的一句话反馈（≤30字，通俗易懂）
"""
```

**优点**：可以综合考虑多个维度输出更自然的建议文字  
**缺点**：成本较高（每次调用约 0.01-0.05 元）；输出不稳定；需人工审核建议库

## 5. 置信度提升策略

### 5.1 分层置信度模型

建议将报告置信度分为三层独立评估：

```
置信度 = f(视频质量置信度, 关键点置信度, 参数可信度)

视频质量置信度（Video Quality Score, VQS）
├─ 关键区域入镜完整度（身体遮挡比例）
├─ 帧率稳定性（是否有大量丢帧）
├─ 图像清晰度估算（Laplacian 方差）
└─ 拍摄角度合适度（基于躯干中心线与垂直线夹角）

关键点置信度（Keypoint Confidence Score, KCS）
├─ 平均 visibility 分数（MediaPipe 输出）
├─ 关键点缺失率（< 5% 为高置信）
└─ 关键点轨迹平滑度（抖动过多为低置信）

参数可信度（Parameter Reliability Score, PRS）
├─ 阶段切分成功率（切出了预期数量的周期？）
├─ 各参数是否在物理合理范围内（骨盆位移 > 10cm 不可信）
└─ 参数内部一致性（腹部收缩时速度是否合理？）
```

**综合置信度计算**：
```
Confidence = 0.4 × VQS + 0.35 × KCS + 0.25 × PRS

高置信度: ≥ 0.75 → 正常出报告
中置信度: 0.55-0.74 → 出报告 + 黄色提示「部分结果仅供参考」
低置信度: < 0.55 → 不出结论性报告 → 强烈建议重新录制

⚠️ 注意：上述阈值（0.75 / 0.55）为初始经验值，尚未基于真实患者数据验证。
需在第二阶段（收集 ≥ 50 条已标注视频）后通过 ROC 曲线重新校准。
```

### 5.2 降级策略

当置信度不足时，系统应降级输出而非硬性判断：

| 置信度级别 | 降级输出策略 |
|------------|-------------|
| 高（≥0.75） | 输出完整报告：总分 + 四维评分 + 建议 |
| 中（0.55-0.74） | 输出简化报告：总分 + 主要问题（1 条）+ 「本次分析仅供参考」 |
| 低（<0.55） | 不输出结论性分数：仅提示「视频质量不足，无法完成分析」+ 改善拍摄建议 |
| 质量检测不通过 | 视频上传时拦截：直接拒绝分析，返回具体质量问题 |

### 5.3 关键点质量增强策略（代码级别）

```python
class KeypointQualityEnhancer:
    """
    增强关键点质量的预处理器
    在 DataPreprocessor 之后运行
    """
    
    def enhance(self, frames: list) -> list:
        frames = self._fill_missing_by_interpolation(frames)  # 线性插值填充缺失帧
        frames = self._smooth_by_savgol(frames, window=5)     # Savitzky-Golay 平滑
        frames = self._reject_physically_impossible(frames)   # 过滤物理不合理值
        frames = self._normalize_to_subject_height(frames)    # 按人体高度归一化
        return frames
    
    def _fill_missing_by_interpolation(self, frames):
        """
        对置信度 < 0.5 的关键点进行线性插值
        最多连续插值 5 帧（超过则整段标记为不可用）
        """
        for kp_name in CRITICAL_KEYPOINTS:  # 仅处理核心关键点
            confidences = [f['keypoints'][kp_name]['confidence'] for f in frames]
            missing_mask = [c < 0.5 for c in confidences]
            # 检测连续缺失段
            gaps = find_continuous_gaps(missing_mask)
            for start, end in gaps:
                if end - start <= 5:  # 短缺口插值
                    interpolate_linear(frames, kp_name, start, end)
                else:
                    mark_segment_unreliable(frames, start, end)
        return frames
    
    def _normalize_to_subject_height(self, frames):
        """
        以肩-髋距离作为人体参考尺度进行归一化
        消除拍摄距离不同导致的量纲差异
        """
        # 取静息阶段（前 30 帧）的平均肩-髋距离作为参考尺度
        rest_frames = frames[:30]
        ref_scale = np.mean([
            euclidean(f['keypoints']['left_shoulder'][:2], 
                     f['keypoints']['left_hip'][:2])
            for f in rest_frames
        ])
        for frame in frames:
            for kp in frame['keypoints'].values():
                kp['x'] /= ref_scale
                kp['y'] /= ref_scale
        return frames
```

### 7.2 视频质量检测增强

```python
class VideoQualityChecker:
    
    def check(self, video_path: str) -> QualityReport:
        report = QualityReport()
        
        # 1. 基础格式检测
        report.fps = self._get_fps(video_path)
        report.duration = self._get_duration(video_path)
        report.resolution = self._get_resolution(video_path)
        
        # 2. 画面清晰度（Laplacian 方差，越高越清晰）
        sharpness = self._calc_sharpness(video_path, sample_frames=10)
        report.sharpness_ok = sharpness > 100  # 经验阈值
        
        # 3. 摄像头稳定性（帧间背景运动向量）
        camera_motion = self._calc_camera_motion(video_path)
        report.camera_stable = camera_motion < 0.05  # 5% 像素移动
        
        # 4. 人体完整性（检测躯干、髋、膝是否入镜）
        body_coverage = self._check_body_coverage(video_path)
        report.body_complete = body_coverage > 0.85
        
        # 综合质量分
        report.quality_score = (
            0.3 * int(report.sharpness_ok) +
            0.3 * int(report.camera_stable) +
            0.4 * body_coverage
        )
        return report
```

## 8. 有效周期计算机制详解

有效周期（Valid Cycle）是参数统计建模的最小单元，指一次完整的「收缩 → 保持 → 回正」往返过程。整个检测分为四步。

### 8.1 选择「驱动信号」

不同动作用不同的物理量来代表波峰/波谷，每帧均从 MediaPipe 关键点实时计算：

| 动作 | 切分驱动信号 | 计算公式 | 极值方向 | 备注 |
|------|------------|---------|----------|------|
| **缩腹运动** | 躯干角度（肩中-髋中连线与垂直轴夹角） | `degrees(arctan2(肩中X - 髋中X, -(肩中Y - 髋中Y)))` | 找极大值（呼吸/动作节奏驱动的周期微波峰） | 与参数计算信号完全分离，避免选择偏差 |
| **骨盆倾斜** | 双髋连线角度 | `degrees(arctan2(右髋Y - 左髋Y, 右髋X - 左髋X))` | 找极大值（倾斜顶峰角度最大） | — |
| **膝关节旋转** | 双膝中点 X 轴横向偏移 | `(L_knee_x + R_knee_x) / 2`，找偏移极大值 | 找极大值（双膝向右倾倒到最大位移时 X 增大） | 正面拍摄，原三点夹角法在正面信号退化 |

### 8.2 移动平均平滑

```python
win = min(5, max(2, len(signal) // 15))   # 窗口大小约为总帧数的 1/15
smoothed = np.convolve(signal, np.ones(win)/win, mode="same")
```

MediaPipe 逐帧输出存在抖动噪声，平滑后波峰形状更稳定，防止把体位微晃动误识别为一次完整动作。

### 8.3 用 `scipy.find_peaks` 检测极值点

```python
centered = smoothed - np.mean(smoothed)    # 去均值，消除全局偏移
min_dist = max(3, int(SAMPLE_FPS * 1.5))   # 相邻两峰最短间距 = 1.5 秒

# 缩腹：直接找极大值（躯干角度在动作节奏点短暂升高后回正，形成波峰）
# 骨盆倾斜：直接找极大值（倾斜角在峰值最大）
peaks = find_peaks(centered,  distance=min_dist, prominence=0.003)

# 膝关节旋转：双膝中点X轴横向偏移，直接找极大值（双膝向右倾到最大位移时 X 增大）
peaks = find_peaks(centered,  distance=min_dist, prominence=0.01)  # prominence 提至 0.01 过滤噪声
```

两个关键参数的含义：

| 参数 | 值 | 作用 |
|------|----|------|
| `distance` | ≥ 1.5s 对应帧数 | 同一次动作不被切成两个峰 |
| `prominence` | 0.003（归一化坐标） | 过滤背景噪声造成的微小假峰 |

### 8.4 以相邻峰为边界切周期

```python
for i, peak in enumerate(peaks):
    # 起点 = 上一个峰（没有则往前推 3s）
    st = peaks[i-1] if i > 0 else max(0, peak - SAMPLE_FPS*3)
    # 终点 = 下一个峰（没有则往后推 3s）
    en = peaks[i+1] if i < len(peaks)-1 else min(last_frame, peak + SAMPLE_FPS*3)
    
    dur = timestamps[en] - timestamps[st]
    if dur < 1.5:    # 过滤太短的伪周期
        continue
    cycles.append({ "start_frame": st, "end_frame": en, ... })
```

**示意图**（以 4 个极值点为例）：

```
信号波形（缩腹 Y 轴，已翻转展示）：
    ∧     ∧     ∧     ∧
   / \   / \   / \   / \
  /   \ /   \ /   \ /   \
      P1    P2    P3    P4   ← 4 个极值点

切分边界：
  |──P1──|──P2──|──P3──|──P4──|
  周期1   周期2   周期3   周期4
  起点=0  起=P1  起=P2  起=P3
  终点=P2 终=P3  终=P4  终=末
```

每个周期的起点 = 上一个峰帧号，终点 = 下一个峰帧号，天然地把「收缩→保持→回正」完整一次往返包含在内。

### 8.5 有效性判断三条件

| 判断条件 | 参数来源 | 说明 |
|---------|---------|------|
| 信号突出度 ≥ 0.003 | `prominence` | 排除背景噪声造成的假峰 |
| 周期时长 ≥ 1.5 秒 | `dur < 1.5 → skip` | 排除动作太快、不完整的片段 |
| 相邻峰间距 ≥ 1.5 秒 | `distance` | 同一次动作不重复计数 |

只有同时通过三条件的周期才进入后续参数计算和统计建模。

## 9. 单镜头最佳拍摄角度规范

### 9.1 核心问题

MediaPipe Pose 基于 **2D 图像** 推断姿态，摄像头角度直接决定哪些关键点可见、哪些代理指标可靠。不同动作对拍摄角度的敏感性不同。

### 9.2 各动作最优角度

#### 缩腹运动 → 正侧面（90° 侧拍）⭐⭐⭐

- 驱动信号是**肩髋中点 Y 轴位移**；侧面视角下躯干前屈/伸直在画面中 Y 轴变化最大，极值点检测信噪比最高
- 正面拍摄时躯干前屈在画面里几乎没有 Y 轴变化，极值检测会完全失效
- 侧面同时可观察骨盆代偿（腰弓起伏）

#### 骨盆倾斜 → 正面（0° 正拍）⭐⭐⭐

- 驱动信号是**双髋连线角度** `arctan2(右髋Y - 左髋Y, 右髋X - 左髋X)`
- 正面视角下左右髋的 X 坐标间距最大，角度变化最灵敏
- 侧面拍摄时左右髋点几乎重叠，X 坐标差接近 0，arctan2 数值跳动剧烈、不可用

#### 膝关节旋转 → 正面 0°⭐⭐⭐（V1.2 方案变更后更新）

- 驱动信号新方案改为**双膝中点 X 轴横向偏移**
- 正面最佳：双膝左右偏移展现为 X 坐标变化，信噪比最高，左倾/右倾方向清晰可辨
- 侧面不可用：侧面拍摄时双膝的 X 坐标差异极小，信号退化为噪声
- 斜前方 45° 次选（X 轴信号略有衰减，但仍可用）

### 9.3 综合推荐（单镜头只能选一个）

**→ 正侧面（90° 侧拍）+ 距离 2.5 ~ 3 米**

| 角度 | 缩腹 | 骨盆倾斜 | 膝关节旋转 | 综合评分 |
|------|------|---------|----------|----------|
| **正面 0°** | ❌ 差 | ✅ 最好 | ✅ 最好（V1.2） | ⭐⭐⭐ |
| **侧面 90°** | ✅ 最好 | 🟡 一般 | ❌ 不可用（V1.2） | ⭐⭐ |
| 斜前方 45° | 🟡 一般 | 🟡 一般 | 🟡 次选（V1.2） | ⭐⭐⭐ |
| 斜后方 135° | ❌ 差 | 🟡 一般 | ❌ 差 | ⭐ |

> **V1.2 推荐策略变更**：膝关节旋转方案改为双膝中点X轴横向偏移后，**正面拍摄**同时入选骨盆倾斜 + 膝关节旋转，成为单默头最优解。缩腹训练仍推荐侧面拍摄，如同时涉及多种动作建议配置两个摄像头或分开预约。

### 9.4 拍摄规范（更新 5.4 节实施细则）

| 拍摄要求 | 推荐值 | 关键原因 | 自动检测方式 |
|----------|--------|---------|-------------|
| **拍摄角度** | **侧面 90°**（或斜前方 45°） | 最大化各动作代理信号幅度 | 躯干中心线与垂直线夹角检测 |
| **摄像头高度** | 与患者髋部等高（约 1m） | 减少透视畸变，关键点投影更准确 | 髋点 Y 坐标在画面中位置检测 |
| **拍摄距离** | 2.5 ~ 3 米 | 确保全身（头顶到脚踝）入画 | MediaPipe 全身关键点置信度 |
| **背景** | 纯色、无杂乱物体 | 提升 MediaPipe 前景分割置信度 | 背景复杂度估算 |
| **光线** | 正面补光，不逆光 | 避免轮廓模糊和关键点丢失 | 图像亮度分布检测 |
| **着装** | 贴身运动服 | 宽松衣物遮蔽关节点，置信度骤降 | 提示文字（无法自动检测） |
| **摄像头稳定** | 三脚架/支架固定 | 消除摄像头抖动引入的伪位移 | 帧间背景运动向量 |
| **无他人入镜** | 仅患者本人 | 避免 MediaPipe 识别错误身体 | 人体检测数量 |

> ⚠️ **与当前教学视频的对照**：现有教学视频置信度 0.74、关键点缺失率 29%，大概率源于拍摄角度或遮挡问题。若改为侧面 90° 重新拍摄教学视频后重跑 `extract_gold_standard.py`，切分精度和统计可信度会有明显改善。
