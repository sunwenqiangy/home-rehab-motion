# 缩腹切分与评分：上线交接清单（2026-10-15）

> 本文记录当前实现，供下一次发布核对；不是临床疗效评价或自动发布授权。以实际发布镜像、运行环境变量和新上传视频的分析快照为最终依据。

## 一、当前口径

运行配置为 `ABDOMINAL_SEGMENTATION_MODE=shadow`、`ABDOMINAL_VISUAL_SCORE_MODE=evidence` 时：

| 场景 | 内部切分 | 正式计次和评分 | 对照结果 |
| --- | --- | --- | --- |
| 小程序新上传的缩腹短片段 | A 姿态峰值、B 姿态闭环、C 腹部轮廓均运行 | **C** 的完整周期计次；`abdominal_visual_evidence_v1` 视觉规则分 | A、B 只作切分诊断；不进行正式姿态模板比较，也不以 A/B 为 C 失败时的自动兜底 |
| 管理端流程验证缩腹视频 | 同样比较 A、B、C | **A** 姿态峰值计次与姿态模板评分 | B 可按姿态模板试算；C 可按视觉规则试算，也可用 C 周期边界套姿态模板做交叉诊断。试算不改写正式结果 |

小程序内部仍先计算旧 `visual_practice` 分，再按 `evidence` 模式用视觉证据分替换正式结果；因此报告只采用一个正式分数，并非两种分数加权或取高。`evidence_shadow` 模式仅保存新分试算，`legacy` 模式保留旧视觉分。这两个开关只影响**新分析**；历史视频不自动重算。

C 的正式数字分要求：腹部轮廓可观察、切出 1～25 个完整周期、画质检查通过且置信度为 high。不满足时保存记录和原因，但不把不可观察解释为用户没有训练，也不拿 A/B 分数冒充 C 分。当前证据分是 `70 + 10×保持 + 10×回位 + 10×节奏` 的规则分，未经过统计概率校准，不表示康复效果。

## 二、金标准与阈值边界

- 管理端的 `standard_action_template`／金标准 `threshold_config`、参考均值和特征单位，作用于**姿态关键点模板评分**：A 的正式分、B 的姿态试算，以及“C 周期边界套姿态模板”的交叉诊断。它们仍对其他使用姿态模板的动作有用。
- **小程序 C 的正式视觉规则分不读取这套金标准数值或其宽松／严格阈值**。调整管理端缩腹金标准，不会直接改变 C 的切分次数或视觉证据分；姿态模板不兼容也不会单独将 C 的正式分打回待复核。
- C 有自己的硬编码门槛：侧视轮廓有效帧率、明暗对比、峰显著度、完整回位及置信度；评分公式也在视觉评分代码中。目前**没有**管理端可调的 C 专属“宽松／标准／严格”阈值版本。若要让管理端阈值控制 C，必须单独设计视觉配置、版本快照、边界校验和回归测试，不能把姿态角度阈值直接套用到轮廓比例上。

对应代码：`services/analysis-service/app/tasks/analyze_video.py`、`app/core/abdominal_visual_signal.py`、`app/core/visual_practice_score.py`、`app/core/scoring_contract.py`。

## 三、部署前必须确认

1. **固定运行配置**：生产环境显式设置 `ABDOMINAL_SEGMENTATION_MODE=shadow`、`ABDOMINAL_VISUAL_SCORE_MODE=evidence`，并确认 `analysis-worker` 实际收到配置。`infra/docker-compose.production.yml` 的 `ABDOMINAL_VISUAL_SCORE_MODE` 缺省值目前仍为 `legacy`；不要依赖缺省值。本地 `.env` 不能代替生产环境配置。
2. **发布同版镜像并重启 Worker**：切分、视觉提取与评分在 Celery worker 内执行；仅重启分析 API 或管理端页面不会让旧 worker 加载新代码。分析 API、worker、主服务报告接口、管理端和小程序版本需按同一口径验证。
3. **时长和容量**：小程序缩腹上传与视觉分析均以 30 秒为上限；管理端流程验证的视觉分析上限为 300 秒。全局 `MAX_ANALYSIS_DURATION_SECONDS` 应至少为 300；`MAX_ANALYSIS_FRAMES=1200` 会使长视频降低实际抽帧率但保留时间跨度。C 需二次解码原视频，300 秒素材要在 staging 实测 CPU、内存、单任务耗时、Celery 队列积压与超时；不能只按 30 秒素材估算容量。
4. **模板与数据溯源**：确认姿态模板特征版本／单位兼容，供 A/B 与交叉诊断使用；确认新结果保存 `segmentation_version=abdominal_visual_v1`、`count_source=visual`、`score_type=visual_evidence`、`score_mode=evidence`、`score_available` 与 `threshold_snapshot`。历史 `visual_practice`、`pose` 结果保留原版本，不批量覆盖或跨口径比较。
5. **失败与隐私边界**：轮廓不可见、肩髋锚点缺失、画质不足、0 次完整周期和非目标内容都要分别验收。未评分不是 0 分；小程序不应展示后台姿态试算、金标准调试信息或其他用户视频。发布审批、备份、隐私和健康检查仍按《线上发布运行指南》执行。

## 四、staging 最小验收

- 小程序：各上传一段独立的 1 次、2 次、轮廓不可观察和不完整回位素材；核对计次、分数或未评分原因、报告与历史页展示，以及训练日是否保留。
- 管理端：上传约 20 秒和约 114 秒的缩腹素材；确认 A 仍是正式结果，B/C 是对照；114 秒 C 不再因旧 30 秒上限跳过。再测超过 300 秒的上传边界，不能导致 worker 长时间占用或虚构分数。
- 对同一视频检查原始快照与页面：C 轮廓周期、C 视觉规则分、C 边界套姿态模板分是不同字段；模板不兼容或无周期时显示原因而非 0 分。
- 记录版本、环境变量、视频 ID、分析耗时、轮廓有效帧率、三种次数与正式分。不同衣着／背景、静止或非缩腹视频要纳入后续验证；重复上传同一素材不能当作独立样本。

## 五、异常处理与回滚

若上线后 C 的未评分率、误计次、任务耗时或队列积压异常，先停止扩大流量并保留快照与视频 ID，按《线上发布运行指南》回滚镜像／配置。把 `ABDOMINAL_SEGMENTATION_MODE` 改成 `legacy_peak` 会把**新**小程序缩腹结果改回姿态路径，属于产品口径变化；把评分模式改成 `evidence_shadow` 或 `legacy` 也会改变患者分数展示，不能当作无感技术回滚。任何切换都需重启 worker、验证报告，并明确告知运营与产品；旧结果不自动重算。
