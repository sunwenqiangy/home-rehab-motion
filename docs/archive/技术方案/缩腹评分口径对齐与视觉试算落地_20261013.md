# 缩腹评分口径对齐与视觉边界试算

> 2026-10-13。目标是让分数可解释、可复现、可回退，而非保证某条视频提分。视觉轮廓仅在管理端流程验证试运行；未经动作负责人和临床人员复核，不接管患者正式计次或评分。

## 已确认的问题

413 的正式 `abdominal_peak_v1` 切分为 0–11.5 秒、11.5–23.9 秒，评分 57.8、95.8，平均 76.8。视觉轮廓接受 1.1–7.2 秒完整周期，拒绝 8.1–17.6 秒候选（未回到准备基线）。使用当前评分器只替换边界，首段约 53.9 分；切分本身不能解决评分口径问题。

当前缩腹计算器的 `abdominal_displacement` 是肩髋屈曲角度（`deg`），`displacement_velocity` 是角速度（`deg/s`）。413 使用的模板 19 却将两项标为 `%`、`%/s`。在核实来源前，不能仅改写单位标签来沿用旧阈值。后续对源视频 298 的逐次特征和关键点复算证实：19 的参考数值实际上来自角度特征，错误主要在单位元数据；证据及修复见文末。

## 本轮代码落地

1. 分析快照增加 `feature_schema_version=abdominal_pose_v2` 和 `scoring_contract`。契约检查逐项核对模板的特征定义版本与单位；旧模板 19 会得到 `incompatible`。患者正式评分在模板不兼容时转待复核，后台流程验证保留诊断分。
2. 仅 `admin_flow_verify` 且视觉信号可观测时，按视觉算法**接受的完整周期**重新计算当前姿态特征和四维分，写入 `segmentation_snapshot.visual_score_preview`。被拒绝候选不试算、不计入平均。若模板不兼容，结果标为 `provisional_incompatible_template`，只能用于定位边界对特征值的影响。
3. 管理端流程验证页并排显示正式分与视觉试算分，提示模板兼容性。旧记录没有新快照，需要重新发起分析才会显示。
4. 从内部金标准视频生成缩腹新模板时，源记录必须带有 `abdominal_pose_v2` 特征版本；否则拒绝“旧数值换新标签”。新生成的候选模板写入相同版本标识与 `deg/deg/s` 单位。生成仍不自动启用。

## 下一阶段：同口径候选模板

1. 选取明确可用的内部金标准原视频，核对原始视频、机位与人工完整周期边界。旧金标准记录若缺 `feature_schema_version`，先用当前分析服务**重新分析源视频**，不能直接拿旧 `motion_feature_result` 统计。重分析属于显式的管理操作，本轮不自动执行。
2. 在同一 `abdominal_pose_v2` 计算器、相同抽帧率和选定切分口径下，生成**未启用**候选模板。记录源视频、切分版本、特征版本、样本数、单位和阈值。现有系统只从一条源视频的多个周期统计：这些周期不是独立受试者，不能把 `n_cycles` 当作人群样本数。
3. 由动作负责人确认“腹部隆起顶点”与示教视频一致；由临床人员确定可接受动作、明显代偿和不完整动作的判定。对姿态角度分与视觉体表分分别定标，不能共用同一幅度模板。
4. 对已标注的 398、399、407、413 及不同衣着/遮挡/半程回落负例批量回放，比较：完整周期数、顶点平台与人工标注重叠、每项特征原值、阈值标签、每次分数、视频平均分及误判原因。按**视频**划分验证集，不能把同一视频裁片当作独立验证样本。

## 正式切换门槛

- 模板特征版本、单位、计算窗口与运行时完全一致；不兼容时不得输出确定性新评分。
- 完整周期和拒绝候选边界经人工复核；视觉不可观测时仍保留待复核路径，不通过放宽阈值伪造周期。
- 分数能区分人工认可的合格动作与明显不完整/代偿动作；不能仅以“413 分数提高”作为通过标准。
- 候选模板先在流程验证中灰度对照，保存版本与回退路径；临床确认后才单独决定是否启用正式视觉计次和新评分。

当前阶段的预期结果是**可对比、可发现不兼容、可生成同口径候选模板**；正式评分提升多少尚不能承诺。现有模板 19 和历史评分保留用于追溯。
