方案摘要
本方案面向造口患者出院后的居家腹部肌肉训练场景，建设一套以微信小程序为患者入口、以服务端视频解析与动作评价模型为核心、以 Web 管理端为医护内容与数据管理入口的自助式康复训练系统。项目不再覆盖金标准动作采集流程，而是将既有金标准动作数据建模为可计算、可比对、可迭代的数据资产，用于后续患者视频分析、动作评价和优化建议生成。

## 1. 项目背景与建设目标

造口旁疝是造口患者常见远期并发症之一，多发生于术后 1 年内。腹部肌肉训练能够增强腹壁肌力，有助于延缓造口旁疝发生。但在居家场景中，患者训练往往缺少姿势评价参数、动作质量评价指标和客观反馈机制，导致训练质量和依从性难以保障。
本项目的建设目标是：围绕“居家训练动作是否达标、动作哪里存在问题、患者是否持续训练”三个核心问题，构建一套轻量、可解释、可运营的自助式腹部肌肉训练系统。患者通过微信小程序录制或上传训练视频，服务端自动解析动作参数并与既有金标准数据模型比对，最终输出动作评价和优化建议；护士长或管理员通过 Web 管理端维护指导内容、查看患者视频和分析结果。

| 建设目标 | 说明 |
| --- | --- |
| 患者侧 | 降低使用门槛，支持查看指导内容、录制或上传视频、查看动作评价与优化建议。 |
| 医护侧 | 支持指导视频和文字内容维护，查看患者上传视频、基础信息和动作分析结果。 |
| 技术侧 | 将已有金标准动作数据建模为标准动作模板、动作阶段模型、动作参数模型、评分模型和建议模板。 |
| 科研侧 | 沉淀结构化训练数据，为后续监督学习模型、运动模式聚类和个体化康复分析提供基础。 |

参考论文一提出的居家康复动作评价系统采用“2D 姿态估计 - 数据预处理 - ROM 分类 - 代偿分类 - 重复次数与有效性判断”的模块化架构，并将动作评价拆解为 ROM 完整性和代偿动作识别两个重点任务。该理念适合作为本项目服务端动作分析流程的基础。
参考论文二围绕居家康复设备采集的高维时序数据，使用 K-means、层次聚类、PAM、CLARA 等无监督聚类方法识别运动模式，并进一步分析 BMI、年龄、性别、疼痛评分等因素对运动模式归属的影响。该理念适合作为本项目第二期长期数据分析和个体化模型建设的基础。

## 3. 总体业务流程与系统架构

### 3.1 核心业务流程

1. 护士长或管理员在 Web 管理端录入指导视频、动作要点、拍摄要求和常见错误。
2. 患者在微信小程序查看指导内容，按要求录制训练视频或上传已录制视频。
3. 服务端接收视频后，完成视频质量检测、关键点/标记点提取、坐标归一化和动作阶段切分。
4. 服务端计算三类动作的核心参数，并与金标准动作模板进行比对。
5. 系统生成动作评分、有效/无效判断、主要问题和动作优化建议。
6. 患者在小程序查看结果，护士长/管理员在 Web 管理端查看视频、用户信息和分析结果。

| 流程环节 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- |
| 指导内容管理 | 标准视频、文字说明、拍摄要求 | 内容编辑、上架、版本管理 | 小程序可展示的动作指导内容 |
| 视频上传 | 患者录制或本地视频 | 格式、大小、时长、动作类型校验 | 待分析视频任务 |
| 视频解析 | 原始视频 | 质量检测、关键点提取、去噪、归一化 | 结构化关键点时序数据 |
| 动作分析 | 关键点时序数据、动作类型 | 阶段切分、参数计算、模板比对 | 动作参数和差异结果 |
| 评价建议 | 参数差异、评分规则、建议模板 | 综合评分、问题识别、建议生成 | 患者报告和管理端分析结果 |

### 3.2 系统架构

系统采用“小程序轻交互、服务端重分析、管理端重维护”的架构。微信小程序只负责训练入口、视频提交和结果查看；复杂的视频解析、动作建模和评分逻辑集中在服务端，便于统一升级和模型版本管理；Web 管理端用于维护指导内容和查看用户数据。

| 层级 | 模块 | 职责 |
| --- | --- | --- |
| 应用层 | 微信小程序 | 患者指导内容展示、视频录制/上传、分析状态展示、结果报告、历史记录。 |
| 应用层 | Web 管理端 | 指导内容管理、用户信息查看、视频查看、分析结果查看、管理员备注。 |
| 服务层 | 视频服务 | 上传、转码、压缩、存储、访问权限控制。 |
| 服务层 | 动作分析服务 | 关键点提取、坐标预处理、动作阶段切分、参数计算、评分。 |
| 服务层 | 模型与规则服务 | 标准模板调用、阈值管理、评分规则、建议模板、模型版本。 |
| 数据层 | 业务数据库与对象存储 | 用户、视频、解析数据、评价结果、指导内容、模型配置。 |

## 4. 微信小程序功能设计

患者端设计以简洁为核心，只保留患者真正需要的动作指导、视频提交、结果查看和历史记录。避免在患者端展示过多专业角度、坐标和算法细节。

| 页面 | 核心功能 | 设计要点 |
| --- | --- | --- |
| 首页 | 开始训练、指导内容、我的记录 | 突出“开始训练”主入口，展示最近一次分析结果和今日是否已上传。 |
| 指导内容页 | 查看动作指导视频、动作要点、常见错误、拍摄要求 | 每个动作使用固定模板：动作目的、动作要点、拍摄要求、常见错误、开始录制/上传。 |
| 录制/上传页 | 立即录制、上传本地视频、选择动作类型 | 上传前提示拍摄角度、光线、身体入镜范围；支持视频格式和时长校验。 |
| 分析中页 | 展示视频上传、解析中、评价中、已完成或失败状态 | 分析耗时可能为异步，使用明确状态降低用户等待焦虑。 |
| 结果报告页 | 展示总体评价、有效次数、主要问题、优化建议 | 患者端使用“优秀/合格/需改进/无效”等可理解等级，不展示复杂原始参数。 |
| 历史记录页 | 查看历史上传视频、动作类型、评分和报告 | 按时间倒序展示，便于患者回看训练变化。 |

| 患者端结果展示字段 | 说明 |
| --- | --- |
| 总体评价 | 优秀、合格、需改进、无效。 |
| 动作完成情况 | 有效次数、无效次数、平均保持时间。 |
| 动作准确性 | 动作幅度或角度是否接近标准。 |
| 稳定性 | 躯干、骨盆或髋部是否稳定。 |
| 主要问题 | 本次最明显的 1-2 个问题。 |
| 优化建议 | 面向患者的简洁动作改进提示。 |
| 重新上传 | 当视频质量不足或动作无效时，支持重新录制/上传。 |

| 指导内容管理 | 维护动作指导视频、动作说明、常见错误、拍摄要求。 | 新增、编辑、上传视频、上下架、排序、版本记录。 |

## 6. 服务端动作分析流程

服务端动作分析流程是本项目的核心链路，应优先保证可解释性、可追溯性和稳定性。参考论文一的模块化设计，本项目将视频分析拆为视频质量检测、关键点/marker 提取、数据预处理、动作阶段切分、参数计算、模板比对、评分与建议生成七个步骤。

| 步骤 | 处理内容 | 输出 |
| --- | --- | --- |
| 1. 视频质量检测 | 检测视频格式、时长、清晰度、光线、身体关键区域是否完整入镜、关键点可见性。 | quality_status、quality_score、quality_issues。 |
| 2. 关键点/marker 提取 | 从视频中提取腹部、躯干、骨盆、髋、膝、踝等关键点或可识别标记点。 | 逐帧关键点坐标与置信度。 |
| 3. 数据预处理 | 置信度过滤、异常点插值、平滑去噪、身体尺度归一化、初始姿势归一化。 | 可用于参数计算的标准化时序数据。 |
| 4. 动作阶段切分 | 根据动作类型切分静息、执行、保持、回正等阶段。 | phase_label、rep_id、阶段起止时间。 |
| 5. 参数计算 | 计算腹部位移、骨盆倾斜角、膝旋转角、稳定性、保持时间、平滑度等指标。 | motion_feature_result。 |
| 6. 金标准比对 | 与标准动作模板的均值、标准差、分位区间和有效范围进行比对。 | 偏差程度、是否达标、低/中/高风险标签。 |
| 7. 评分与建议 | 生成综合评分、有效/无效次数、主要问题、患者建议和管理端解释。 | video_evaluation_result、advice_summary。 |

对于普通上传视频，系统需要在报告中保留“识别置信度”概念。当视频角度、遮挡或关键点缺失导致计算结果可靠性下降时，应提示用户重新拍摄，避免将低质量视频强行输出高确定性的医学评价。

## 7. 数据建模体系设计

数据建模的核心任务，是把既有金标准动作数据转化为服务端可调用的标准模型，并建立患者视频解析结果与金标准模型之间的比对机制。该体系不是单一模型，而是一组围绕动作、阶段、参数、阈值、评分和建议的结构化模型。

### 7.1 建模原则

1. 可解释优先：一期以金标准模板、专家阈值和规则评分为主，避免直接依赖不可解释黑盒模型。
2. 动作拆解优先：每个动作拆成阶段、参数和代偿类型，而不是只输出“对/错”。
3. 模板可版本化：金标准模板、参数阈值、评分权重和建议规则均需保留版本号。
4. 患者视频可追溯：每个评价结果应可回溯到原始视频、关键点数据、参数结果和规则版本。
5. 为二期预留：一期沉淀的结构化数据要能支持后续监督学习、聚类和个体化模型。

### 7.2 核心数据模型

| 模型 | 用途 | 核心字段 |
| --- | --- | --- |
| 标准动作模板模型 | 存储已有金标准动作数据形成的标准轨迹、统计参数和有效区间。 | template_id、action_type、version、keypoint_schema、phase_schema、reference_stats、status。 |
| 动作阶段模型 | 定义动作从开始到结束的阶段顺序和合法跳转。 | action_type、phase_code、phase_name、start_condition、end_condition、required_order、duration_range。 |
| 动作参数模型 | 定义每类动作需要计算哪些参数以及计算方法。 | feature_code、feature_name、action_type、unit、calculation_method、normal_range、warning_range、invalid_range、weight。 |
| 视频解析模型 | 保存患者视频解析后的逐帧关键点和置信度。 | video_id、frame_index、timestamp、keypoint_name、x、y、z/proxy_z、confidence。 |
| 动作评价模型 | 保存单次动作和整段视频的评分与判定结果。 | rep_id、video_id、accuracy_score、stability_score、control_score、duration_score、valid_flag、compensation_type。 |
| 建议模板模型 | 将参数异常映射为患者端建议和管理端解释。 | advice_code、action_type、trigger_condition、patient_text、nurse_text、priority。 |
| 模型版本模型 | 记录标准模板、阈值、评分规则和算法版本。 | model_version、effective_time、change_log、operator、status。 |

### 7.3 标准动作模板统计结构

对于每个动作和每个关键参数，建议从金标准数据中沉淀以下统计信息，既支持模板匹配，也支持阈值评分。

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| mean | 金标准均值 | 作为标准中心值。 |
| std | 金标准标准差 | 用于均值 ± 标准差的容忍区间。 |
| min / max | 金标准极值 | 用于识别明显异常值。 |
| p25 / p50 / p75 | 分位数 | 用于更稳健的非正态数据阈值。 |
| valid_range | 专家确认的有效区间 | 作为动作是否达标的优先依据。 |
| warning_range | 轻微偏差区间 | 用于生成“需改进”建议。 |
| invalid_range | 明显错误区间 | 用于判定动作无效或重新上传。 |

## 8. 三类核心动作模型设计

### 8.1 缩腹运动模型

缩腹运动主要训练腹横肌和核心稳定。由于普通视频或动作捕捉无法直接测量腹横肌本身收缩，本项目应使用“腹壁体表位移/腹部厚度变化的替代指标”评价缩腹完成情况。

| 参数 | 计算/解释 | 评价意义 |
| --- | --- | --- |
| 腹部收缩幅度 abdominal_displacement | Δd = d_rest - d_draw_in；表示腹壁前表面相对参考平面的后移距离。 | 判断是否真正完成腹部向内收缩。 |
| 收缩保持时间 contraction_duration | 达到有效收缩阈值后的连续持续时间。 | 判断训练是否充分。 |
| 躯干角度变化 trunk_angle_delta | 当前躯干角度相对初始姿态的变化。 | 判断是否通过抬起躯干代偿。 |
| 骨盆水平偏移 pelvis_shift | 骨盆参考点在水平面上的相对移动。 | 判断骨盆是否稳定。 |
| 动作平滑度 movement_smoothness | 基于位移曲线速度、加速度或 jerk 计算。 | 判断动作控制能力和抖动情况。 |

合格判定建议：腹部收缩幅度达到金标准有效区间，且躯干角度变化、骨盆水平偏移未超过阈值，保持时间达到要求。

### 8.2 骨盆倾斜运动模型

骨盆倾斜运动重点评价骨盆前倾/后倾角度是否达标，同时判断骨盆水平偏移、躯干代偿和下肢代偿。

| 参数 | 计算/解释 | 评价意义 |
| --- | --- | --- |
| 骨盆倾斜角 pelvic_tilt_angle | ASIS_m = (LASIS + RASIS)/2；PSIS_m = (LPSIS + RPSIS)/2；θ = arctan((z_ASISm - z_PSISm) / sqrt((x_ASISm - x_PSISm)^2 + (y_ASISm - y_PSISm)^2))。 | 判断骨盆前倾/后倾幅度。 |
| 骨盆倾斜变化量 pelvic_tilt_delta | Δθ = θ_current - θ_initial。 | 判断动作相对初始姿势是否达到目标区间。 |
| 骨盆水平偏移 pelvis_horizontal_shift | 骨盆中心点在水平面上的位移。 | 判断是否左右平移或整体偏移。 |
| 躯干角度变化 trunk_angle_delta | 躯干参考线相对初始姿态变化。 | 判断是否通过躯干带动动作。 |
| 保持时间 hold_duration | 达到目标角度区间后的持续时间。 | 判断动作是否稳定保持。 |

合格判定建议：骨盆倾斜角变化量达到目标区间，骨盆水平偏移和躯干角度变化未超阈值，保持时间达到处方要求。

### 8.3 膝关节旋转运动模型

膝关节旋转运动主要用于下肢协调和核心控制训练。评价重点包括膝关节旋转角度、髋部稳定性、骨盆/躯干代偿、保持时间和动作平滑度。

| 参数 | 计算/解释 | 评价意义 |
| --- | --- | --- |
| 膝关节旋转角 knee_rotation_angle | 优先使用股骨坐标系与胫骨坐标系的相对旋转，提取绕纵轴的内旋/外旋角；普通视频可使用髋-膝-踝关键点投影夹角作为 proxy 指标。 | 判断旋转幅度是否达到目标范围。 |
| 髋部稳定性 hip_stability | 髋部关键点位移或角度变化。 | 判断是否通过髋部带动代偿。 |
| 骨盆旋转变化 pelvis_rotation_delta | 骨盆参考点构成平面的旋转变化。 | 判断骨盆是否明显代偿。 |
| 躯干旋转变化 trunk_rotation_delta | 躯干参考点旋转或角度变化。 | 判断上半身是否跟随旋转。 |
| 动作平滑度 smoothness | 旋转曲线速度、加速度和抖动。 | 判断动作控制能力。 |

需要特别说明：金标准模型中可以保存三维动作捕捉角度；患者普通视频上传场景下，若无法稳定获得三维 marker 信息，应输出“估计角度/proxy 指标”和识别置信度，避免将普通视频估计结果表述为高精度三维测量。

## 9. 评分与建议生成模型

### 9.1 综合评分模型

综合评分建议采用四维结构：动作准确性、稳定性、动作控制和保持时间。不同动作可调整权重，但整体应保持一致的评价口径。

| 评分维度 | 含义 | 基础权重 |
| --- | --- | --- |
| 动作准确性 | 角度、位移、ROM/幅度是否接近金标准。 | 40% |
| 稳定性 | 躯干、骨盆、髋部是否保持稳定。 | 25% |
| 动作控制 | 动作是否平滑、是否抖动、是否过快。 | 20% |
| 保持时间 | 是否达到要求的持续时间。 | 15% |

| 等级 | 分数 | 患者端展示 | 处理建议 |
| --- | --- | --- | --- |
| 优秀 | ≥90 | 动作完成很好 | 记录有效训练。 |
| 合格 | 75-89 | 动作基本达标 | 记录有效训练，并给出轻微优化建议。 |
| 需改进 | 60-74 | 动作存在明显问题 | 记录为需改进，提示重点纠正。 |
| 无效 | <60 | 建议重新练习或咨询医护 | 不计入有效训练，提示重新上传或联系医护。 |

### 9.2 建议生成规则

建议生成不建议直接使用大模型自由生成，而应采用“参数触发 + 规则模板”的方式，确保建议可解释、可审核、可追溯。

| 触发条件 | 患者端建议 | 管理端解释 |
| --- | --- | --- |
| trunk_angle_delta 超过阈值 | 请保持上半身稳定，避免通过抬起身体完成动作。 | 躯干角度变化超过稳定性阈值，疑似躯干代偿。 |
| pelvis_shift 超过阈值 | 请保持骨盆稳定，动作幅度可以先减小。 | 骨盆水平偏移较大，疑似骨盆代偿。 |
| hold_duration 低于阈值 | 请在动作完成后保持数秒再缓慢放松。 | 保持时间不足，动作持续性未达标。 |
| abdominal_displacement 低于阈值 | 请尝试缓慢将腹部向内收紧，不要只移动上半身。 | 缩腹幅度不足，腹壁位移未达到有效区间。 |
| confidence_score 低于阈值 | 本次视频识别不够清晰，建议按拍摄要求重新上传。 | 关键点置信度低，分析结果可靠性不足。 |

## 10. 两期建设规划

项目仅分两期建设：第一期完成可用系统、核心数据建模和规则评价闭环；第二期将原先的模型优化与长期分析能力合并建设，包括监督学习模型、长期趋势分析、聚类分层和个体化建议能力。

| 阶段 | 建设目标 | 核心交付 | 关键验收 |
| --- | --- | --- | --- |
| 第一期：MVP 与规则评价闭环 | 完成微信小程序、Web 管理端、服务端视频解析与金标准模板比对，形成“上传视频 - 解析参数 - 生成评价 - 查看结果”的完整闭环。 | 小程序首页、指导内容、录制/上传、分析中、结果报告、历史记录；Web 内容管理、用户列表、视频查看、分析结果；标准动作模板、阶段模型、参数模型、评分规则、建议模板。 | 用户可上传视频并获得报告；管理员可维护指导内容并查看视频；系统可输出三类动作的核心参数、评分、主要问题和建议；评价结果可追溯到规则版本。 |
| 第二期：模型优化与长期分析能力 | 在第一期沉淀数据基础上，建设监督学习模型、代偿识别优化、长期趋势分析和患者运动模式分层能力。 | 动作阶段分类模型、动作质量分类模型、代偿识别模型、长期训练趋势、运动模式聚类、风险标签、个体化优化建议、科研数据导出。 | 模型效果可量化评估；能够识别常见代偿类型；能够展示患者长期趋势；可基于训练数据形成患者分层和风险提示。 |

| 第二期能力 | 数据基础 | 建模方法建议 | 输出 |
| --- | --- | --- | --- |
| 动作阶段/质量分类 | 第一期积累的关键点时序、阶段标签、评分结果、人工复核结果。 | MLP、Random Forest、XGBoost、TCN/LSTM 等，根据样本量逐步升级。 | 阶段识别、动作质量等级、有效/无效次数。 |
| 代偿识别优化 | 躯干、骨盆、髋部、膝部相关参数与代偿标签。 | 多标签分类模型，结合专家规则做后处理。 | 骨盆代偿、躯干代偿、髋部代偿等标签。 |
| 长期趋势分析 | 多次训练记录、评分、保持时间、代偿频次、上传间隔。 | 时间序列统计、移动平均、趋势斜率、异常检测。 | 依从性下降、质量下降、疼痛/不适风险提示。 |
| 运动模式聚类 | 多周期训练数据和结构化参数。 | K-means、层次聚类、PAM、CLARA、DBSCAN 等，使用 silhouette score 评估。 | 稳定进步型、依从不足型、代偿频繁型、平台停滞型等分层。 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 普通视频角度不标准 | 关键点识别不稳定，参数误差增加。 | 小程序强化拍摄提示；服务端增加视频质量检测；低置信度时提示重新上传。 |
| 腹部收缩无法直接测量肌肉 | 容易误把体表位移当作肌肉收缩。 | 产品和报告中统一表述为“腹壁体表位移/腹部厚度变化替代指标”。 |
| 三维金标准与二维视频之间存在差异 | 患者视频与金标准的直接比较可能存在系统误差。 | 建立 2D/proxy 指标映射层；输出置信度；必要时按视频采集方式分别建模。 |
| 早期患者样本不足 | 直接训练复杂模型泛化风险高。 | 第一期以专家规则和金标准模板比对为主，第二期再基于真实数据训练模型。 |
| 建议内容需要医学审核 | 自动建议可能存在表述风险。 | 采用规则模板，所有建议由护士长/管理员审核后上架。 |
| 视频涉及隐私 | 医疗数据合规风险。 | 权限控制、视频脱敏策略、访问日志、数据加密和最小化展示。 |
