## 3. 患者端补充设计

### 3.1 老年友好模式默认开启

患者端小程序在 V2 中默认采用**老年友好模式**，目标是降低理解成本、减少误操作、提升训练依从性。

核心策略包括：

- 默认使用大字号、大触控区与高对比度视觉方案
- 重要说明默认展开，减少折叠与二次点击
- 核心按钮尽量使用满宽主按钮，降低选择负担
- 使用图文并重、正误对比、步骤图示的方式替代抽象说明
- 对关键结果提供视觉、震动、提示音等多模态反馈
- 一期仅保留适老化统一模式，不再提供标准模式切换；P09 "我的页"中仅保留字号微调、震动/声音开关等辅助设置，取消模式切换入口

### 3.2 患者端页面补充重点

| 页面 | V2 补充重点 |
|------|-------------|
| 首页 | 重构首页模块架构为 8 区纵向布局：今日训练 → 反馈提醒 → 快速开始 → 本周进展 → 阶段状态 → 最近训练 → 训练提示卡片；消息提醒紧跟主卡片展示 |
| 指导页 | 强化步骤图、拍摄示意图、错误 GIF，降低理解门槛；底部操作栏固定 |
| 上传页 | 从"技术确认页"升级为"拍摄合规引导 + 提交决策页"；主按钮固定底部 |
| 分析中页 | 用更清晰的过程说明降低等待焦虑；按钮采用页尾策略（等待态） |
| 报告页 | 使用动态分阶段反馈替代固定问题列表；主按钮固定底部，次按钮页尾 |

## 4. 报告页反馈机制升级

### 4.1 从单一纠错改为三阶段反馈

V1 的报告页更偏向“指出问题 + 给建议”。在 V2 中，报告页改为根据患者训练阶段动态切换主视角，形成更符合康复训练过程的反馈逻辑。

| 阶段 | 典型条件 | 主视角 |
|------|----------|--------|
| 纠错期 | 新手、评级较低、置信度偏低 | 明确问题、帮助纠正 |
| 巩固期 | 已连续多次合格，但仍有局部可优化项 | 巩固进步、轻量优化 |
| 激励期 | 已连续稳定达标 | 强化成就、鼓励坚持 |

> 一期先按该规则执行，同时要求后台支持参数化配置（如新手次数阈值、连续达标次数、时间窗口），便于后续校准。

### 4.2 三阶段展示原则

#### A. 纠错期

重点帮助患者“知道哪里错、怎样改”。

- 仅突出 1-2 个最主要问题，避免信息过载
- 使用“错误做法 vs 正确做法”的对比方式呈现
- 建议文案采用患者友好表述，不暴露技术参数
- 提供回看指导内容的快捷入口，支持再次练习

#### B. 巩固期

重点帮助患者“知道自己已经做得不错，并理解如何继续变稳”。

- 增加明确的肯定反馈
- 只保留 1 条轻微优化建议
- 强调与上次相比的进步，降低挫败感

#### C. 激励期

重点帮助患者“持续坚持，而不是完成后流失”。

- 展示连续达标天数、本周训练次数、平均得分等成就信息
- 展示徽章或成就触发结果
- 用趋势与鼓励文案强化“继续练有意义”

### 4.3 报告页补充原则

- 保留综合评分与四维评价，但不要求患者依赖图表理解
- 雷达图之外必须有文字摘要
- 不设计语音播报按钮，避免增加认知负担
- 一期不支持语音反馈输入，患者反馈仅支持文字 + 图片
- 可保留系统提示音，但不作为报告页显式功能入口

## 5. 激励与成就体系补充

### 5.1 设计目标

V2 将依从性设计从单页体验提升为贯穿患者旅程的系统能力，目标包括：

- 提高首次训练完成率
- 提高 3 天、7 天、30 天持续训练率
- 降低“做完一次后不再回来”的流失概率
- 让患者感受到“训练有进步、坚持有成果”

### 5.2 跨页激励设计

| 页面 | 激励方式 | 作用 |
|------|----------|------|
| 首页 | 今日训练状态、鼓励文案、连续训练感知 | 促开始 |
| 指导页 | 训练前鼓励语 | 降低畏难 |
| 上传页 | 拍摄通过即时正反馈 | 降低中途放弃 |
| 报告页 | 分阶段反馈 + 成就强化 | 提升结果体验 |
| 历史页 | 趋势回顾、达标次数、成就展示 | 强化长期价值 |
| 我的页 | 总训练次数、连续坚持天数、徽章展示、辅助设置（字号/震动/声音） | 形成沉淀感 |

### 5.3 一期徽章体系（简化版）

| 徽章 | 获得条件 | 意义 |
|------|----------|------|
| 初次尝试 | 完成第一次训练 | 帮助迈出第一步 |
| 连续 3 天 | 连续 3 天完成训练 | 强化早期习惯形成 |
| 连续 7 天 | 连续 7 天完成训练 | 强化稳定坚持 |
| 首次优秀 | 第一次获得优秀评级 | 强化能力进步感 |
| 坚持 30 天 | 累计训练 30 天 | 形成长期目标 |

### 5.4 激励文案使用原则

- 面向患者使用鼓励性、陪伴性语言
- 不因单次结果较差造成打击感
- 优先强调“坚持”和“进步”，弱化“失败”感受
- 当评分下降时，采用温和安抚表述，避免焦虑

### 5.5 激励元素推荐落位

为避免激励体系只停留在策略层，建议一期按如下方式落到具体页面：

| 页面 | 推荐落位 | 推荐展示内容 |
|------|----------|--------------|
| P02 首页 | 今日训练卡片下方 / 欢迎区下方 | 连续训练天数、今日鼓励文案、最近获得徽章 1 个 |
| P07 报告页 | 综合评价卡片下方 / 激励期专属区 | 本次进步、连续达标天数、新获得徽章、高亮鼓励文案 |
| P08 历史页 | 统计概览卡片下方 | 最新 3 个徽章、累计达标次数、近 7 天趋势摘要 |
| P09 我的页 | 训练概况下方独立分区 | 徽章墙、最近获得时间、辅助设置入口（字号微调、震动/声音开关） |

建议优先展示输入内容如下：
- 连续训练天数
- 最近一次评分变化（较上次 +X / -X）
- 最近获得徽章
- 累计达标次数
- 近 7 天训练频次
- 鼓励文案（按首次训练 / 连续 3 天 / 连续 7 天 / 首次优秀 / 评分进步触发）

## 6. 反馈机制闭环补充

### 6.1 增补背景

V1 中患者端主要完成“看指导—上传视频—看报告”的训练链路，但缺少患者主动提问与医护闭环处理能力。V2 增补训练反馈闭环，用于承接患者对报告理解、动作执行、身体不适、上传问题等场景的反馈。

### 6.2 产品边界

本反馈能力的边界是：

- **服务于训练相关问题反馈**
- **不替代医疗问诊**
- 对于疼痛、不适等高风险内容，仅提供引导与提醒，不给出诊断结论

### 6.3 闭环能力定义

V2 的反馈能力包括四个环节：

1. 患者在报告页提交反馈
2. 系统将反馈同步到医护端待处理队列
3. 医护端完成回复与状态流转
4. 患者端收到回复通知，并可查看处理结果

### 6.4 患者端反馈入口

- 入口挂载在报告页中
- 支持反馈类型选择、文字描述、图片补充
- 一期不支持语音输入，避免增加实现与审核复杂度
- 对“身体不适”类反馈展示安全提示，建议及时联系医生

### 6.5 医护端处理要求

| 能力 | 要求 |
|------|------|
| 列表管理 | 支持按优先级与时间排序 |
| 详情查看 | 可查看反馈内容、关联训练记录、患者信息 |
| 回复 | 以文字回复为主，支持规范话术 |
| 状态流转 | 待处理 → 处理中 → 已回复 → 已关闭 |
| 高优先级识别 | 身体不适类自动高亮 |

### 6.6 通知能力补充

V2 一期即引入站内通知能力，并在首页右上角提供消息入口，用于承接以下事件：

- 视频分析完成
- 医护回复反馈
- 获得新徽章
- 其他关键训练提醒

## 7. Web 管理端补充设计

### 7.1 M08 指导内容编辑页升级

V2 将 M08 从“文本 + 视频”的基础内容维护页，升级为支持多媒体教学资产管理的内容编辑中心。

### 7.2 新增内容资产类型

| 资产类型 | 产品用途 |
|----------|----------|
| 极简说明 | 面向老年患者的一句话概括说明 |
| 步骤示意图 | 直观解释动作要点 |
| 拍摄示意图 | 解释拍摄角度、距离、光线要求 |
| 错误演示图 / GIF | 直观展示常见错误动作 |

### 7.3 升级目标

- 让医护端能维护更适合老年患者理解的内容资产
- 让小程序指导页内容从“文字说明”升级为“图文 + 动图 + 视频”的多模态指导
- 让管理端预览区能直接模拟患者端实际展示效果
- 支撑后续内容版本化和更细粒度优化

### 7.4 V2 对 M08 的要求

- 左侧继续承担内容编辑，右侧继续承担实时预览
- 预览统一展示适老化模式效果，不再区分标准/适老双模式预览
- 上架前继续要求关键字段校验
- 内容保存仍保留版本记录能力
