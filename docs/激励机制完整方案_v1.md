# 自助式腹部肌肉训练系统 · 激励机制完整方案

**版本**：V1.0  
**日期**：2026-07-25  
**适用范围**：微信小程序（患者端）、主服务、Web 管理端  
**关联能力**：训练上传、分析报告、训练历史、徽章、站内通知、阶段规则

---

## 1. 方案目标与产品定位

本方案用于建立一套面向康复训练患者的低压力激励机制，帮助患者持续完成训练、感知动作逐渐稳定，并看见与过去自己的比较变化。

激励机制不定位为游戏化打榜、积分商城或分数竞赛，而是训练陪伴能力。系统统一传递以下价值：

> **坚持，让练习不断；稳定，让动作更扎实；进步，让每一次练习都有意义。**

### 1.1 设计目标

1. 提升首次训练后的继续训练意愿，降低“一次练完即流失”。
2. 让不同基础、不同恢复阶段的患者都能获得合理正反馈。
3. 不为激励目的降低评分标准，保持分析与动作指导的可信度。
4. 让患者理解“今天完成训练”和“动作表现如何”是两件可同时成立的事。
5. 用跨页面一致的进度、文案、徽章与通知形成连续体验。
6. 避免制造连续记录焦虑、分数焦虑或过度训练诱导。

### 1.2 非目标

一期不建设以下能力：

- 患者排行榜、好友对比、地区排名。
- 积分商城、兑换、抽奖、付费任务。
- 以高分为目标的冲榜或挑战赛。
- 因连续记录中断而产生惩罚、清零提示或负向通知。
- 基于诊断、病情改善、疗效承诺的医疗结论。

## 2. 核心决策

### 2.1 坚持与评分解耦

**坚持类进度按“成功上传并确认分析”计算，不以分析评分是否合格为前提。**

患者完成训练上传并在上传确认页点击“确认分析”后，即视为当天完成训练；同一自然日最多记 1 个训练日。

分析评分保持专业标准，不因激励目的放宽。评分及分析结果用于动作指导、稳定性变化、保持时间变化和质量型成就判断。

```text
上传成功并确认分析
  → 记为当天完成训练
  → 累计连续训练 / 本周训练 / 坚持类徽章进度

分析完成
  → 告知动作表现与下一步建议
  → 判断过程性进步
  → 判断质量型成就（如首次优秀）
```

### 2.2 患者可见表达

患者侧不直接使用“有效训练”“无效训练”“未达标”“连续记录中断”等工程或负向术语。

推荐表达：

- `今天的训练已记录`
- `本周已完成 3 / 7 天训练`
- `您已连续训练 4 天`
- `这次比上次更稳了一些`
- `今天重新开始也很好`

### 2.3 计入训练日的最低条件

以下条件全部满足时，才计入当天训练日：

1. 视频文件上传成功。
2. 文件通过基础校验：格式、最短时长、可读取性、文件大小等。
3. 患者在上传确认页主动点击“确认分析”。
4. 不是同日重复计数的视频；同一天只累计一次训练日。
5. 非空文件、非损坏文件、非重复文件哈希。

以下情况不计入训练日：

- 患者取消上传；
- 上传失败；
- 文件损坏或基础校验不通过；
- 仅选择视频但没有确认分析；
- 同一天的重复上传。

分析结果为“需改进”、质量不足、分析失败或分析中，不回滚已确认的当天训练记录；它们分别通过报告页给出动作指导、重拍建议或状态说明。

### 2.4 防止过度训练

- 每自然日最多累计 1 个训练日。
- 首页明确表达“每天完成 1 次训练即可”，不鼓励一天多次上传以获得更多奖励。
- 当天已完成训练后，首页改为“今天的训练已经完成，注意休息，明天再继续”。
- 身体不适、安全分流状态下不展示冲刺目标、徽章进度或额外训练引导。
- 不使用“冲刺”“挑战”“再练一次即可领奖”等可能诱导过量训练的文案。

## 3. 激励体系结构

```text
完成训练上传并确认分析
  ↓
训练坚持统计更新
  ├─ 总训练次数
  ├─ 本周训练天数
  ├─ 连续训练天数
  └─ 坚持类徽章进度
  ↓
分析结果生成
  ├─ 动作指导
  ├─ 稳定性 / 保持时间 / 分数变化
  ├─ 过程性进步提示
  └─ 质量型成就判断
  ↓
激励事件生成
  ├─ 报告页即时反馈
  ├─ 首页进度和鼓励文案更新
  ├─ 历史页趋势沉淀
  ├─ 我的页成就沉淀
  ├─ 徽章中心更新
  └─ 低频站内通知
```

### 3.1 四条激励线

| 激励线 | 核心问题 | 数据依据 | 患者感受 |
|---|---|---|---|
| 训练坚持 | 今天是否完成训练、是否形成习惯 | 确认分析后的训练日 | 我一直在坚持 |
| 练习投入 | 新手尚未稳定时如何认可努力 | 已完成分析的练习次数 | 我在认真练习 |
| 稳定进步 | 如何看见动作逐步变好 | 与个人历史的稳定性、保持时间、分数等比较 | 我比以前更稳 |
| 成就沉淀 | 如何形成长期回顾与获得感 | 徽章、累计训练日、首次优秀 | 坚持看得见成果 |

### 3.2 训练结果与激励关系

| 训练状态 / 结果 | 计入总训练次数 | 计入训练日 / 连续训练 | 可产生过程性进步提示 | 可触发质量型成就 |
|---|---:|---:|---:|---:|
| 上传成功并确认分析 | 是 | 是（同日最多一次） | 等待分析完成 | 等待分析完成 |
| 优秀 | 已计入 | 已计入 | 是 | 是 |
| 合格 | 已计入 | 已计入 | 是 | 可选，不新增一期质量型徽章 |
| 需改进 | 已计入 | 已计入 | 是 | 否 |
| 无效 / 质量不足 | 已计入训练日 | 已计入训练日 | 否 | 否 |
| 分析失败 | 已计入训练日 | 已计入训练日 | 否 | 否 |
| 未确认分析 / 上传失败 | 否 | 否 | 否 | 否 |

说明：训练坚持认可患者完成训练的投入；质量结果负责指导患者如何练得更稳。质量不足、分析失败不应被误称为“动作完成得好”，但不否定患者已经完成当天训练的事实。

## 4. 统一指标与数据口径

所有患者端页面必须消费同一套服务端摘要，禁止自行从历史列表推算本周天数、趋势或徽章状态。

### 4.1 统一激励摘要

```typescript
interface MotivationSummary {
  // 坚持与投入
  totalTrainingCount: number;
  totalTrainingDays: number;
  consecutiveTrainingDays: number;
  weeklyTrainingDays: number;
  weeklyTargetDays: number;

  // 质量与进步
  totalQualifiedCount: number;
  latestGrade?: "优秀" | "合格" | "需改进" | "无效";
  scoreDelta?: number;
  stabilityDelta?: number;
  durationDelta?: number;
  validRepsDelta?: number;
  improvementLevel: "none" | "slight" | "clear";
  improvementType?: "score" | "stability" | "duration" | "reps";
  improvementMessage: string;

  // 成就与阶段
  stage: "fix" | "consolidate" | "encourage";
  badges: BadgeItem[];
  latestBadge?: BadgeItem;
  nearestBadge?: BadgeProgress;
  encourageText: string;
  todayTrainingState: "not_started" | "confirmed" | "analyzing" | "reported";
}

interface BadgeProgress {
  code: BadgeCode;
  current: number;
  target: number;
  unit: "天";
  message: string;
}
```

### 4.2 指标定义

| 指标 | 定义 | 患者展示名称 |
|---|---|---|
| 总训练次数 | 上传成功并确认分析的次数 | 总训练次数 |
| 累计训练日 | 至少完成一次确认分析的自然日数量 | 累计训练日 |
| 连续训练天数 | 连续自然日完成训练的天数 | 连续训练 |
| 本周训练天数 | 最近 7 个自然日中完成训练的自然日数量 | 本周训练 |
| 总达标次数 | 分析评级为合格或优秀的训练次数 | 累计达标次数 |
| 过程性进步 | 与患者自己历史训练相比的改善 | 比上次更稳 / 保持更久 |
| 首次优秀 | 首次获得优秀评级 | 首次优秀成就 |

## 5. 过程性进步机制

### 5.1 适用范围

即使训练结果是“需改进”，只要患者相对自己的最近可比训练出现清晰改善，仍应展示过程性进步提示。

过程性进步不影响连续训练、坚持徽章；它只用于认可动作正在逐步变稳的过程。

### 5.2 比较规则

优先按同动作类型、最近一次已完成分析的历史记录比较。比较优先级为：

1. 保持时间变化；
2. 稳定性变化；
3. 有效动作次数变化；
4. 综合分变化。

若没有足够的历史记录，不显示“进步 / 退步”比较，只展示本次可执行建议。

### 5.3 建议阈值

| 指标 | 轻微进步 | 明显进步 |
|---|---:|---:|
| 综合分 | +3 分 | +8 分 |
| 稳定性 | +3 分 | +8 分 |
| 保持时间 | +0.5 秒 | +1.5 秒 |
| 有效次数 | +1 次 | +2 次 |

阈值由服务端配置管理；患者端只渲染服务端给出的 `improvementLevel`、`improvementType` 和 `improvementMessage`。

### 5.4 文案规则

| 场景 | 推荐文案 |
|---|---|
| 需改进但稳定性提升 | 这次身体更稳了一些，继续把动作放慢就会更好。 |
| 需改进但保持时间提升 | 这次保持时间更长了，已经比上次更接近目标。 |
| 合格且有进步 | 这次比上次更稳，继续保持现在的节奏。 |
| 优秀 | 这次动作完成得很稳定，您的努力正在看到成果。 |
| 分数持平 | 这次表现保持得很稳定，坚持练习会越来越熟练。 |
| 分数下降 | 这次有些波动没关系，按这次提示慢慢调整就好。 |

禁止使用“退步”“失败”“错误很多”“必须达到”“落后”等高焦虑表达。

## 6. 徽章体系

一期采用“坚持类徽章 + 质量类徽章”的双轨模型。

### 6.1 坚持类徽章

坚持类徽章只依据确认分析后的训练日，不依赖分析评分。

| 徽章 | 编码 | 获得条件 | 患者文案 |
|---|---|---|---|
| 🏁 初次尝试 | `first_try` | 首次完成训练并确认分析 | 迈出第一步，就是很好的开始。 |
| 🔥 连续 3 天 | `streak_3` | 连续 3 个自然日完成训练 | 连续 3 天练习，好习惯正在慢慢养成。 |
| 💪 连续 7 天 | `streak_7` | 连续 7 个自然日完成训练 | 您已经坚持 1 周，稳定练习很了不起。 |
| 🏅 坚持 30 天 | `days_30` | 累计 30 个训练日 | 累计坚持 30 天，每一份认真都值得纪念。 |
| 🏆 坚持 60 天 | `days_60` | 累计 60 个训练日 | 累计坚持 60 天，稳定练习已经成为您的好习惯。 |
| 🌟 坚持 90 天 | `days_90` | 累计 90 个训练日 | 累计坚持 90 天，您用长期坚持留下了很棒的成果。 |

### 6.2 质量类徽章

| 徽章 | 编码 | 获得条件 | 患者文案 |
|---|---|---|---|
| ⭐ 首次优秀 | `first_excellent` | 分析完成后，首次获得优秀评级 | 第一次获得优秀，您的努力正在看到成果。 |

一期不增加更多质量型徽章，避免评分机制尚未完全个体化时对患者造成不必要压力。

### 6.3 徽章进度提示

只展示最近、最容易理解的一个未完成目标；同一时间不展示多个待完成任务。

| 当前状态 | 推荐提示 |
|---|---|
| 连续 2 天 | 再完成 1 天训练，就能点亮“连续 3 天”徽章。 |
| 连续 6 天 | 再坚持 1 天，就能完成连续 7 天训练。 |
| 累计 29 天 | 再完成 1 天训练，就能获得“坚持 30 天”徽章。 |
| 累计 59 天 | 再完成 1 天训练，就能获得“坚持 60 天”徽章。 |
| 累计 89 天 | 再完成 1 天训练，就能获得“坚持 90 天”徽章。 |

当患者提交后尚在分析、处于身体不适安全分流、或当天已经完成训练时，不展示“再练一次即可获得”的目标提示。

### 6.4 徽章事件化与唯一性

徽章不能只在接口读取时根据当前数据临时推导；必须记录真实获得事件。

```text
训练上传确认 / 分析报告完成
  ↓
计算当前满足的徽章
  ↓
与 user_badge 已获得记录对比
  ↓
找出本次 newlyUnlockedBadges
  ↓
写入 user_badge
  ↓
创建 badge 通知
  ↓
报告页展示一次性成就卡
```

徽章记录建议字段：

| 字段 | 说明 |
|---|---|
| `userId` | 患者 ID |
| `badgeCode` | 徽章编码 |
| `earnedAt` | 真实获得时间 |
| `sourceVideoId` | 触发训练视频 ID |
| `sourceReportId` | 可选，质量类徽章关联报告 |
| `notifiedAt` | 徽章通知发送时间 |
| `seenAt` | 患者端查看时间 |

唯一约束：`(userId, badgeCode)`。

## 7. 三阶段激励策略

阶段判定仍由已有后台规则控制，但前端必须将阶段转换为不同的表达重点。

### 7.1 纠错期：建立信心

适用：新患者、训练次数较少、置信度偏低、动作尚未稳定。

- 认可完成训练与练习投入。
- 报告只突出 1～2 个最主要的调整点。
- 如有过程性进步，优先展示“更稳 / 保持更久”。
- 不突出分数、连续目标和徽章任务。

示例：

> 今天的训练已记录。先把呼吸和回正动作放慢，慢慢练就会越来越熟悉。

### 7.2 巩固期：强化稳定性

适用：已有训练基础，尚未形成稳定连续表现。

- 首页突出本周训练天数与连续训练天数。
- 报告突出与上次相比的稳定变化。
- 仅保留一条轻量优化建议。
- 可展示最近一个徽章目标。

示例：

> 您已经做得不错了，这次继续把节奏放稳。

### 7.3 激励期：强化长期成果

适用：训练习惯稳定，达到激励期规则条件。

- 强调连续训练、本周完成、累计训练日、最新徽章。
- 报告可展示累计达标次数及个人趋势摘要。
- 鼓励坚持，不鼓励额外加量。

示例：

> 保持现在的训练习惯，每一次练习都在积累成果。

## 8. 患者端跨页面设计

### 8.1 首页：促开始与今天的积累

首页只回答三个问题：今天是否需要训练、当前已积累什么、下一步是什么。

推荐顺序：

```text
今日训练卡
  ↓
本周训练进度
  ↓
连续训练天数
  ↓
当前鼓励语
  ↓
最近获得徽章 / 最近目标
  ↓
快速开始训练
  ↓
最近训练
```

训练前示例：

> 今天还没训练  
> 完成 1 次训练，就能积累今天的坚持进度。

训练确认分析后示例：

> 今天的训练已完成  
> 您已连续训练 3 天。分析完成后，我们会告诉您这次哪里更稳。

当天完成后示例：

> 今天的训练已经完成  
> 注意休息，明天再继续。

首页不显示“连续记录中断”“未达标次数”“距离合格还差多少”。

### 8.2 指导页：降低畏难

指导详情页顶部增加一条阶段化训练前鼓励：

| 阶段 | 文案 |
|---|---|
| 纠错期 | 别着急，跟着步骤慢慢做就可以。 |
| 巩固期 | 您已经做得不错了，这次继续把节奏放稳。 |
| 激励期 | 保持现在的训练习惯，每一次练习都在积累成果。 |

指导页不展示复杂指标、分数或多个徽章任务。

### 8.3 上传确认页：即时正反馈

| 场景 | 文案 |
|---|---|
| 基础质量通过 | 拍得很清楚，可以放心提交分析。 |
| 有轻微问题 | 视频基本清楚，调整一下会让分析更准确。 |
| 基础校验不通过 | 这段视频暂时不适合分析，重新拍一次会更可靠。 |
| 确认分析成功 | 今天的训练已记录，分析完成后会告诉您动作哪里更稳。 |

### 8.4 报告页：即时反馈与下一步

报告页展示优先级：

1. 本次训练结果与一句话总结；
2. “今天训练已记录”状态；
3. 过程性进步或稳定表现；
4. 新解锁徽章；
5. 本周训练 / 连续训练摘要；
6. 一个下一步动作建议；
7. 再练一次入口。

不同场景：

| 场景 | 首要表达 |
|---|---|
| 需改进但有进步 | 今天的训练已记录 + 比上次更稳 + 一个调整点 |
| 需改进且无明显进步 | 已完成今天的练习 + 一个调整点 |
| 合格 | 今天的训练已记录 + 稳定表现 + 连续训练进度 |
| 优秀 | 今天的训练已记录 + 稳定成果 + 首次优秀或徽章 |
| 新徽章 | 一次性成就卡 / 弹层，之后不重复展示 |

徽章弹层示例：

> **获得新徽章：连续 3 天**  
> 您已经连续完成 3 天训练，稳定坚持很了不起。  
> `继续查看报告`

### 8.5 历史页：长期回顾

历史页在训练列表前展示：

- 本周训练：`4 / 7 天`；
- 累计训练日；
- 总训练次数；
- 累计达标次数；
- 最近几次训练的稳定性或保持时间摘要；
- 最新 3 枚徽章。

图表若存在，必须配患者友好文字摘要，例如：

> 最近几次训练的动作更稳定了。

### 8.6 我的页与徽章页：长期沉淀

我的页核心统计：

- 总训练次数；
- 累计训练日；
- 连续训练天数；
- 累计达标次数；
- 最近获得的 3 枚徽章及获得日期。

全部徽章页：

- 已获得 / 未解锁分组；
- 每枚徽章的真实获得时间；
- 未解锁徽章仅展示一个最近目标的进度；
- 新获得徽章从通知跳转后高亮；
- 不展示他人数据、排名或竞争信息。

## 9. 通知与提醒机制

### 9.1 通知范围

一期只发送三类激励通知：

| 类型 | 触发条件 | 频率上限 | 跳转 |
|---|---|---|---|
| 新徽章 | 首次解锁任一徽章 | 每枚徽章仅一次 | 徽章页，高亮新徽章 |
| 明显进步 | 分析完成且达到明显进步阈值 | 同一天最多一次 | 对应训练报告 |
| 温和提醒 | 连续 2 天未完成训练 | 首次提醒后每周最多一次 | 首页或训练页 |

### 9.2 不主动通知的场景

以下信息只在患者主动打开页面时温和展示，不发送站内提醒：

- 单次需改进；
- 分数下降；
- 连续记录未增长；
- 未完成周目标；
- 未解锁徽章；
- 上传失败或质量不足；
- 夜间高频训练提醒。

### 9.3 温和提醒文案

> 这两天没有训练也没关系，方便时可以从一次简单练习重新开始。

> 每次认真练习都在积累，方便时回来练一练吧。

禁止提醒：

- 您已连续 X 天未训练；
- 连续记录即将中断；
- 再不训练就失去徽章。

### 9.4 通知去重

| 事件 | `dedupeKey` |
|---|---|
| 新徽章 | `badge:{userId}:{badgeCode}` |
| 明显进步 | `progress:{userId}:{videoId}` |
| 温和提醒 | `reminder:{userId}:{year-week}` |

## 10. 数据模型与事件机制

### 10.1 训练坚持记录

```typescript
interface TrainingAttendance {
  id: string;
  userId: string;
  videoId: string;
  trainingDate: string;
  countedForTrainingDay: boolean;
  countedAt: string;
  createdAt: string;
}
```

约束：同一患者、同一自然日只能有一条 `countedForTrainingDay = true` 的记录。

### 10.2 训练质量结果

```typescript
interface TrainingQualityOutcome {
  videoId: string;
  userId: string;
  reportStatus: "pending" | "completed" | "quality_insufficient" | "failed";
  grade?: "优秀" | "合格" | "需改进" | "无效";
  score?: number;
  stabilityDelta?: number;
  durationDelta?: number;
  validRepsDelta?: number;
  improvementLevel?: "none" | "slight" | "clear";
  improvementMessage?: string;
  createdAt: string;
}
```

### 10.3 训练激励快照

每次分析完成后生成快照，用于报告回放、历史展示与一次性成就判断。

```typescript
interface TrainingMotivationSnapshot {
  videoId: string;
  userId: string;
  reportId: string;

  trainingCountAfter: number;
  trainingDaysAfter: number;
  consecutiveTrainingDaysAfter: number;
  weeklyTrainingDaysAfter: number;
  qualifiedCountAfter: number;

  improvementLevel: "none" | "slight" | "clear";
  improvementType?: "score" | "stability" | "duration" | "reps";
  improvementMessage: string;

  newlyUnlockedBadgeCodes: BadgeCode[];
  stage: "fix" | "consolidate" | "encourage";
  createdAt: string;
}
```

### 10.4 用户徽章记录

```typescript
type BadgeCode =
  | "first_try"
  | "streak_3"
  | "streak_7"
  | "first_excellent"
  | "days_30"
  | "days_60"
  | "days_90";

interface UserBadgeRecord {
  userId: string;
  badgeCode: BadgeCode;
  earnedAt: string;
  sourceVideoId: string;
  sourceReportId?: string;
  notifiedAt?: string;
  seenAt?: string;
}
```

唯一约束：`(userId, badgeCode)`。

### 10.5 处理时机与幂等性

```text
上传确认分析
  ↓
创建 TrainingAttendance（当天未计入时）
  ↓
更新首页坚持数据与坚持类徽章
  ↓
分析回调成功
  ↓
写入报告与 TrainingQualityOutcome
  ↓
生成 TrainingMotivationSnapshot
  ↓
判断过程性进步、首次优秀等质量型成就
  ↓
创建低频激励通知
```

同一 `videoId` 的激励处理必须幂等：

- 同一视频只累计一次总训练次数与训练日；
- 同一视频只生成一份激励快照；
- 同一徽章不重复写入；
- 同一进步事件不重复发通知；
- 分析回调重试不改变历史快照。

## 12. 管理端设计

激励系统不增加医护逐条运营工作。管理端只承担规则配置、聚合观察和异常排查。

### 12.1 激励规则配置

配置项：

| 分类 | 可配置内容 |
|---|---|
| 训练日规则 | 最低时长、允许格式、同日计数规则、重复文件规则 |
| 进步阈值 | 分数、稳定性、保持时间、有效次数的轻微 / 明显阈值 |
| 阶段规则 | 新手阈值、低置信度阈值、进入激励期的连续合格次数 |
| 提醒频率 | 中断提醒天数、周提醒上限、每日进步通知上限、夜间静默时段 |

一期建议仅系统管理员可修改，普通医护账号仅查看，避免频繁改动影响患者体验一致性。

### 12.2 激励效果概览

只提供聚合指标，不提供患者排名：

- 本周完成训练患者数；
- 首次训练完成率；
- 连续 3 天、7 天训练达成数；
- 30 / 60 / 90 天徽章发放数；
- 首次优秀获得数；
- 明显进步训练数；
- 温和提醒触达数；
- 阶段分布：纠错期、巩固期、激励期。

## 13. 实施优先级

### P0：统一口径与患者表达

1. 上传确认分析后创建训练日记录；
2. 同日最多记 1 个训练日；
3. 将连续训练、本周训练、总训练次数统一改为基于训练日；
4. 评分结果与坚持进度解耦；
5. 修复首页、历史、报告、我的页各自估算指标的问题；
6. 修复报告页负分数展示为“提升 ↑-X 分”的问题；
7. 增加“今天的训练已记录”等患者文案。

### P1：徽章与跨页面闭环

1. 增加 60 天、90 天坚持徽章；
2. 徽章从实时推导改为真实获得事件；
3. 新徽章通知、报告页一次性成就卡、徽章页高亮；
4. 首页展示连续训练、最近徽章与最近目标；
5. 历史页展示累计训练日、累计达标、最近 3 枚徽章；
6. 我的页展示训练次数、训练日、连续训练和最近获得徽章；
7. 指导页、上传确认页补齐低压力鼓励文案。

### P2：低频提醒与运营观察

3. 管理端规则配置；
4. 管理端聚合激励效果看板；
5. 基于真实数据校准进步阈值与文案。

## 14. 验收标准

### 场景一：上传确认即记录坚持

1. 患者上传一条通过基础校验的视频，并在上传确认页点击确认分析；
2. 当天训练状态更新为已完成；
3. 总训练次数增加 1；
4. 当天训练日增加 1；
5. 连续训练和本周训练进度更新；
6. 即使后续分析为需改进，训练日和坚持进度不回滚。

### 场景二：需改进但有过程性进步

1. 患者两次同动作训练都为需改进；
2. 第二次稳定性或保持时间达到进步阈值；
3. 报告页展示“比上次更稳 / 保持更久”；
4. 不发质量型徽章；
5. 首页与训练日进度正常累计；
6. 不显示失败、未达标或连续记录中断文案。

### 场景三：连续 3 天训练

1. 患者在连续 3 个自然日完成上传确认；
2. 第 3 天解锁连续 3 天徽章；
3. 只生成一条徽章通知；
4. 报告页展示一次性成就卡；
5. 首页展示连续训练 3 天；
6. 徽章页显示真实获得日期；
7. 后续训练不重复发放或通知。

### 场景四：60 天、90 天坚持

1. 患者累计完成第 60 个训练日时解锁坚持 60 天徽章；
2. 第 60 天仅发一次对应通知；
3. 患者累计完成第 90 个训练日时解锁坚持 90 天徽章；
4. 徽章页、我的页、首页最近成就均能正确显示；
5. 30 / 60 / 90 天徽章的口径均为累计训练日，不是连续自然日。

### 场景五：连续中断后回归

1. 患者连续两天未完成训练；
2. 系统按频率规则发送一次温和提醒；
3. 患者回归并完成上传确认；
4. 页面展示“今天重新开始也很好”；
5. 不展示“连续记录断了”“清零”“失败”；
6. 新连续训练从 1 天开始计算。

### 场景六：分析回调重复

1. 同一训练分析回调重复到达；
2. 不重复累计训练次数或训练日；
3. 不重复写入徽章；
4. 不重复创建通知；
5. 报告激励快照保持一致。

## 15. 最终体验标准

患者应能自然理解：

- 我今天完成了训练，系统会把我的坚持记录下来；
- 这次动作哪里更稳，报告会告诉我；
- 即使一次没达到预期，认真练习也不是白费；
- 训练日不断累积，3 天、7 天、30 天、60 天、90 天都会留下成果；
- 每次训练只要慢慢来、稳定做，就能逐渐看到属于自己的变化。

这套机制的最终目的不是让患者“追分”，而是帮助患者在安全、低焦虑的节奏中持续训练，并持续感知到自己的坚持、稳定和进步。
