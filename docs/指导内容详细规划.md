# 指导内容详情：理想状态设计

## 1. 设计目标

指导内容模块的目标不是“放一个视频”，而是让患者在训练前完成三件事：

1. **知道这次要练什么**：动作目标、主要步骤；
2. **知道怎样做才更安全、更容易被识别**：动作、呼吸、节奏、拍摄方式；
3. **能立即开始训练**：直接拍摄或从相册选择视频，再进入上传确认和分析。

整体链路：

```text
训练列表
  → 动作指导详情
    → 看教学视频
    → 逐步查看图文动作卡
    → 查看拍摄要求和常见错误
    → 直接打开相机 / 相册
  → 视频上传成功
  → 上传确认页：拍摄质量检查
  → 确认分析
  → 分析中
  → 训练报告
```

核心原则：

- 患者端只看**已发布版本**；
- 教学视频提供完整示范，图文步骤承担“看懂、照做”的任务；
- 老年患者默认看到大字号、完整展开、短句、一图一重点；
- 管理端的编辑结果和患者端展示必须一一对应；
- 未完成的草稿和上传中的素材绝不能影响患者端。

---

# 2. 患者端设计

## 2.1 训练列表页

训练列表继续作为患者进入动作指导的入口，但每张卡片需要展示真实发布内容的摘要。

每张动作卡包含：

| 信息 | 展示方式 |
|---|---|
| 封面图 | 动作示范照片或插画 |
| 动作名称 | 如“缩腹运动训练” |
| 一句话目标 | 如“缓慢收腹，帮助保持核心稳定” |
| 预计时长 | 如“约 3 分钟” |
| 内容更新提示 | 可选，如“已更新动作图示” |
| 操作 | `查看动作指导` |

点击时传递的是**指导内容 ID 与当前发布版本**，而不是仅传 `actionType`：

```text
/pages/training-detail/index?id=guide_abdominal&version=5
```

患者端详情始终按 `id` 获取服务端的已发布内容，不自行拼接默认动作文案。

---

## 2.2 动作指导详情页信息架构

页面保持纵向滚动，底部固定主按钮。建议从上到下分为 7 个区块。

```text
顶部导航
  ↓
动作概览与一句话目标
  ↓
教学视频
  ↓
训练前提醒
  ↓
结构化动作步骤卡
  ↓
拍摄要求卡
  ↓
常见错误对比
  ↓
安全与训练提示
  ↓
固定底部：立即录制 / 从相册选择
```

## A. 顶部导航与动作概览

顶部显示：

- 返回按钮；
- 页面标题：`动作指导`；
- 动作名称；
- 一句话目标；
- 可选的预计训练时长。

示例：

> **缩腹运动训练**  
> 慢慢收紧腹部，保持腰背稳定。  
> 建议用时：约 3 分钟

这里的文字不使用“核心激活”“代偿”等专业词。可在管理端维护一条面向患者的`briefInstruction`。

---

## B. 教学视频区

视频是“完整示范”，而不是唯一学习方式。

### 视频区展示

- 视频封面；
- 播放大按钮；
- 时长；
- 提示：`建议先完整看一遍，再按下面步骤练习`；
- 支持全屏；
- 加载失败时不阻塞页面，展示：

> 教学视频暂时无法播放，您可以先查看下面的图文步骤。

### 视频行为

- 使用小程序原生 `<video>`；
- 自动播放默认关闭；
- 用户点击后播放；
- 支持全屏；
- 第一次播放结束后展示轻提示：

> 视频看完了，下面按步骤再确认一遍会更安心。

---

## C. 训练前提醒

视频下方用一张浅色提示卡，避免患者直接忽略关键风险或准备条件。

示例：

> **开始前请确认**  
> 身体感觉舒适再开始；请准备一块平稳的垫子，并留出活动空间。  
> 如训练中出现疼痛或明显不适，请先停止训练并及时联系主治医生。

它不是医疗建议，而是训练安全边界提示。

---

## D. 结构化动作步骤卡

这是患者端的核心区块，建议每个动作维护 **3～5 步**。

每张步骤卡固定结构：

| 元素 | 内容 |
|---|---|
| 步骤编号 | `步骤 1`、`步骤 2` |
| 照片/插画 | 大图展示，可点击放大 |
| 图片标注 | 箭头、关键部位框选、短标签 |
| 步骤标题 | 如“躺稳，双腿自然弯曲” |
| 一句话说明 | 如“腰背贴住垫子，肩膀放松。” |
| 可选提醒 | 如“不要急着开始收腹。” |

示例：

```text
步骤 1 / 4
[动作示范图：腰背贴垫，双膝屈曲]
腰背贴稳，双腿自然弯曲
肩膀放松，不要急着抬头或收腹。
```

### 展示规则

- 默认全部展开，不设置折叠；
- 一张卡只讲一个重点；
- 图片优先于文字；
- 标题建议不超过 16 字；
- 说明建议不超过 35 字；
- 无图片时不能发布；
- 患者点击图片可全屏预览。

---

## D.1 三个动作的平卧位推荐文案

> 适用原则：缩腹运动、骨盆倾斜、膝关节旋转均在平卧位进行。患者平卧在平整垫面上，动作应缓慢、舒适、无痛；如出现疼痛或明显不适，应停止训练。

### 缩腹运动

- **一句话目标**：慢慢收紧腹部，帮助保持腰背稳定。
- **训练前安全提示**：请平卧在平整垫面上，双脚踩稳；如出现腰腹疼痛、头晕或明显不适，请立即停止训练。

| 步骤 | 标题 | 患者短说明 |
|---|---|---|
| 1 | 仰卧屈膝准备 | 平卧屈膝、双脚踩稳地面，双手轻放在腹部，放松肩颈。 |
| 2 | 缓慢收紧腹部 | 自然呼气时轻轻向内收紧腹部，保持肩背贴稳地面，避免憋气。 |
| 3 | 放松并重复 | 缓慢放松回到自然呼吸，保持平卧姿势稳定后再重复动作。 |

### 骨盆倾斜

- **一句话目标**：轻轻收紧下腹，让腰背更舒适地贴近垫面。
- **训练前安全提示**：请平卧在平整垫面上，在无痛范围内小幅练习；如腰部、髋部或腿部出现疼痛、头晕或明显不适，请立即停止训练。

| 步骤 | 标题 | 患者短说明 |
|---|---|---|
| 1 | 平卧屈膝准备 | 平卧屈膝、双脚踩稳地面，肩颈和腰背保持放松。 |
| 2 | 轻轻后倾骨盆 | 呼气时轻轻收紧下腹，让腰背更贴近地面，动作不要急。 |
| 3 | 回到中立位置 | 吸气后慢慢回到舒适的平卧中立位，避免用力顶起臀部。 |

### 膝关节旋转

- **一句话目标**：平卧轻轻活动双膝，帮助身体放松转动。
- **训练前安全提示**：请平卧在平整垫面上，动作保持缓慢、小幅；如膝盖、髋部或腰背出现刺痛、肿胀、头晕或明显不适，请立即停止训练。

| 步骤 | 标题 | 患者短说明 |
|---|---|---|
| 1 | 平卧屈膝准备 | 平卧屈膝并拢，双脚踩地，双臂自然放在身体两侧。 |
| 2 | 双膝缓慢倾向一侧 | 双膝一起缓慢倒向一侧，骨盆随动作自然转动，肩背尽量贴稳地面。 |
| 3 | 回正后换侧 | 慢慢回到平卧中间位，再向另一侧重复，始终以舒适无痛为准。 |

> 管理端可直接使用“参考视频分析建议”中的关键截图作为上述步骤的示意图，并可按实际教学视频继续微调文案。

## E. 拍摄要求卡

拍摄要求从“说明文字”变成训练前可执行检查。

建议维护 3～4 张拍摄卡：

1. **拍摄角度**
   - 图片：正确机位示意；
   - 文案：`手机放在身体正侧方，与平卧躯干保持平行。`

2. **入镜范围**
   - 图片：绿色正确框选；
   - 文案：`平卧后从头到脚都要拍到，四周留出适当空间。`

3. **光线**
   - 图片：明亮 / 背光对比；
   - 文案：`让平卧身体处于明亮区域，避免背光和阴影遮挡。`

4. **画面稳定**
   - 图片：支架或固定摆放示意；
   - 文案：`请固定手机，训练时尽量不要晃动。`

图片应支持`正确`与`错误`标识：

- `✓ 建议这样拍`
- `× 不建议这样拍`

患者不需要在此页勾选确认；点击底部按钮后直接拍摄/选视频。拍摄质量的正式检查统一放在上传确认页。

---

## F. 常见错误区

常见错误采用“错误动作 + 怎么改”的短卡形式，建议每个动作维护 2～4 条。

例如：

| 错误 | 正确做法 |
|---|---|
| `× 肩膀跟着用力` | `✓ 只慢慢收紧腹部，肩膀保持放松` |
| `× 一直憋气` | `✓ 收腹时慢慢呼气，回正时自然吸气` |
| `× 回正太快` | `✓ 保持后慢慢放松，不要突然松掉` |

每条可选择配 3 秒循环 GIF 或错误对比图。若没有 GIF，至少要有对应文字与静态图；不允许出现“只放 GIF 没有文字”的情况。

---

## G. 固定底部操作栏

底部固定两项操作：

```text
[ 🎥 立即录制训练视频 ]   主按钮、满宽
[ 📁 从相册选择视频 ]     次按钮、独立一行
```

用户点击后的行为：

| 按钮 | 行为 |
|---|---|
| 立即录制训练视频 | 直接调用相机录制 |
| 从相册选择视频 | 直接调用相册选择 |
| 选择/录制成功 | 上传文件 |
| 上传成功 | 跳转上传确认页 |
| 上传确认 | 展示质量检查与视频预览 |
| 确认分析 | 创建分析任务 |

上传确认页承担：

- 视频时长、格式、大小检查；
- 画面清晰度与稳定性提示；
- 是否需要重新拍摄；
- `确认分析`主操作；
- `重新选择视频`次操作。

因此指导详情页不再放复杂的勾选项，保持“先看、再拍”的简单路径。

# 3. 患者端状态设计

| 场景 | 页面表现 |
|---|---|
| 内容加载中 | 视频区与步骤卡使用骨架屏 |
| 指导内容不存在 | 显示“当前动作指导暂未准备好”，返回训练列表 |
| 视频加载失败 | 图文步骤仍可继续使用 |
| 图片加载失败 | 保留步骤文字和图片替代说明 |
| 内容版本已更新 | 下次进入自动看到已发布新版本，不中断已打开页面 |
| 网络异常 | 显示“网络不稳定，请稍后重试”，提供重试按钮 |
| 素材不完整 | 不应暴露给患者；由发布校验阻断 |

# 4. 管理端设计

管理端不是简单的文本表单，而是一个**动作教学内容工作台**。

核心目标：

1. 医护/运营人员能按内容结构维护；
2. 上传真实视频、照片、插画、GIF；
3. 实时看到患者端适老化效果；
4. 草稿不会影响线上患者；
5. 发布前自动拦截不完整内容；
6. 已发布版本可回滚。

---

## 4.1 管理端页面结构

建议分为三个页面：

```text
指导内容列表
  → 指导内容编辑工作台
  → 版本历史 / 发布记录
```

### A. 指导内容列表页

列表按动作展示内容状态：

| 字段 | 示例 |
|---|---|
| 动作 | 缩腹运动 |
| 当前线上版本 | V5 |
| 草稿状态 | 有草稿 / 无草稿 |
| 发布状态 | 已发布 / 未发布 |
| 素材完备度 | 100% |
| 最近发布时间 | 2026-07-24 |
| 操作 | 编辑草稿 / 查看线上效果 / 版本记录 |

建议增加三个筛选条件：

- 发布状态；
- 是否存在草稿；
- 素材是否完整。

---

## 4.2 指导内容编辑工作台

采用三栏或“两栏编辑 + 右侧预览”的布局。

```text
左侧：内容结构导航
中间：当前模块编辑区
右侧：患者端实时预览 + 发布检查
```

### 左侧：内容结构导航

```text
基础信息
教学视频
动作步骤（3/5）
拍摄要求（3/4）
常见错误（2/3）
训练安全提示
发布检查
```

每个模块显示完成状态：

- `✓ 已完成`
- `! 待补充`
- `× 不可发布`

### 中间：模块化编辑区

不要再采用“每行一段文本 + 多张散图”的编辑方式，应改为结构化表单。

---

## 4.3 基础信息编辑

| 字段 | 规则 |
|---|---|
| 动作类型 | 必填，创建后不可轻易变更 |
| 标题 | 必填，≤ 30 字 |
| 一句话目标 | 必填，≤ 40 字 |
| 预计时长 | 必填，如 3 分钟 |
| 训练前安全提示 | 必填，使用平台默认模板，可有限编辑 |
| 封面图 | 必填，患者列表页展示 |

---

## 4.4 教学视频编辑

| 字段 | 规则 |
|---|---|
| 视频文件 | 必填，MP4/MOV，建议 30 秒～3 分钟 |
| 视频封面 | 自动截帧或人工上传 |
| 时长 | 上传后自动读取 |
| 视频说明 | 可选，如“请先完整观看一次” |
| 替代说明 | 必填，视频不可播放时展示 |

上传流程：

```text
选择文件
  → 获取对象存储上传凭证
  → 直传对象存储
  → 服务端校验文件类型、体积、时长
  → 返回稳定 URL、objectKey、封面、时长
  → 写入草稿
```

管理端不能再保存浏览器 `blob:` URL。

---

## 4.5 动作步骤编辑

每个步骤是独立对象，支持排序、增加、删除。

```text
步骤 1
  - 标题
  - 面向患者的短说明
  - 示范图 / 插画
  - 图片标注
  - 替代文本
```

建议字段：

| 字段 | 规则 |
|---|---|
| 步骤序号 | 自动维护，可拖动排序 |
| 步骤标题 | 必填，≤ 16 字 |
| 步骤说明 | 必填，≤ 35 字 |
| 步骤图片 | 必填，JPG/PNG/WebP |
| 图片标注 | 可选，可使用箭头、框选、短标签 |
| 图片替代文本 | 必填，用于图片加载失败兜底与无障碍 |
| 关联视频时间点 | 可选，例如 00:18 |

发布最低要求：

- 至少 3 步，最多 5 步；
- 每步必须有标题、说明、图片、替代文本；
- 禁止步骤顺序重复或缺失。

---

## 4.6 拍摄要求编辑

每条拍摄要求也是结构化卡片：

```text
拍摄要求 1
  - 类型：角度 / 入镜 / 光线 / 稳定
  - 标题
  - 正确示意图
  - 可选错误示意图
  - 患者短说明
```

最低发布要求：

- 至少 3 条；
- 至少覆盖：角度、入镜范围、光线；
- 每条必须有文字和正确示意图；
- 推荐提供错误示意，帮助患者避免常见拍摄问题。

---

## 4.7 常见错误编辑

每条错误使用“错误—改正”模型：

```text
错误项
  - 错误标题
  - 错误说明
  - 正确做法
  - 错误示意图 / GIF
  - 可选正确对比图
```

最低发布要求：

- 至少 2 条；
- 每条必须包含错误说明与正确做法；
- 至少一张错误示意图或 GIF；
- 文字必须是患者可理解表达，不能只写“代偿”“控制力不足”等算法或专业术语。

---

# 5. 实时患者端预览

右侧预览不是静态截图，应基于草稿数据实时渲染，与小程序页面使用相同字段结构：

- 视频封面与播放态；
- 动作概览；
- 每张步骤卡；
- 拍摄要求；
- 常见错误；
- 固定底部双按钮。

预览必须支持三种状态：

| 状态 | 用途 |
|---|---|
| 正常态 | 检查完整的患者页面 |
| 素材加载失败 | 检查替代文本与降级展示 |
| 小屏模式 | 检查老年用户手机上的字号、按钮和信息密度 |

这样编辑者能在发布前确认：

- 图片标注是否清楚；
- 字号是否足够大；
- 文案是否过长；
- 重要提示是否被底部操作栏遮挡；
- 视频、图片、GIF 是否都能加载。

# 6. 草稿、发布与版本机制

## 6.1 内容状态

```text
草稿
  → 完整性校验通过
  → 手动发布
  → 已发布版本
  → 新草稿编辑
  → 再次发布
```

患者端只读取：

```text
publishedVersion
```

管理端可以读取：

```text
draftVersion + publishedVersion + versionHistory
```

## 6.2 发布规则

发布时执行以下校验：

| 模块 | 最低要求 |
|---|---|
| 基础信息 | 标题、一句话目标、预计时长、封面图齐全 |
| 教学视频 | 视频、封面或回退说明齐全 |
| 动作步骤 | 3～5 步；每步有标题、说明、图片、替代文本 |
| 拍摄要求 | 至少 3 条；覆盖角度、入镜范围、光线 |
| 常见错误 | 至少 2 条；每条有错误描述与改正方式 |
| 患者预览 | 完整性检查通过，无阻塞错误 |
| 资产状态 | 没有上传中、上传失败或失效 URL 的资源 |

发布前展示确认弹窗：

> 发布后，患者将看到本次已保存的指导内容。  
> 当前线上版本将保留，可在版本记录中回滚。

## 6.3 回滚规则

- 每次发布生成不可变版本号，例如 `V1`、`V2`；
- 保留至少最近 10 个版本；
- 回滚本质是将历史版本复制为新的草稿，再重新发布；
- 不允许直接篡改已发布历史版本；
- 记录发布人、发布时间和变更摘要。

这样即使某次图片、视频或文案有问题，也能快速恢复。

# 7. 建议数据模型

当前 `points: string[]`、`stepImages: string[]` 这种平行数组不足以支持步骤卡一一对应，应升级为结构化对象。

```typescript
interface GuidanceStep {
  id: string;
  order: number;
  title: string;
  description: string;
  image: GuidanceAsset;
  imageAnnotations: ImageAnnotation[];
  altText: string;
  videoTimestampSeconds?: number;
}

interface ShootingRequirement {
  id: string;
  type: "angle" | "framing" | "lighting" | "stability";
  title: string;
  description: string;
  correctImage: GuidanceAsset;
  incorrectImage?: GuidanceAsset;
  altText: string;
}

interface CommonMistake {
  id: string;
  order: number;
  title: string;
  mistakeDescription: string;
  correction: string;
  media?: GuidanceAsset;
  correctImage?: GuidanceAsset;
}

interface GuidanceAsset {
  objectKey: string;
  url: string;
  thumbnailUrl?: string;
  mimeType: string;
  sizeBytes: number;
  width?: number;
  height?: number;
  durationSeconds?: number;
}

interface GuidanceContentVersion {
  guidanceId: string;
  version: number;
  status: "draft" | "published" | "archived";
  title: string;
  briefInstruction: string;
  estimatedMinutes: number;
  coverImage: GuidanceAsset;
  trainingSafetyNotice: string;
  video: {
    asset: GuidanceAsset;
    coverImage?: GuidanceAsset;
    fallbackText: string;
  };
  steps: GuidanceStep[];
  shootingRequirements: ShootingRequirement[];
  commonMistakes: CommonMistake[];
  publishedAt?: string;
  publishedBy?: string;
}
```

关键变化：

- **步骤、图片、文字不再靠数组位置猜对应关系**；
- 每个图片是带 `objectKey`、类型、体积等信息的真实资源；
- 草稿和已发布版本独立；
- 患者端只拿到已发布版本 DTO；
- 管理端编辑完整草稿 DTO。

# 9. 最终验收标准

完成后，以下场景必须成立：

1. 管理端新建或编辑某动作的草稿，患者端仍只看到旧的已发布版本。
2. 管理端上传教学视频、步骤图、拍摄图和错误 GIF 后，保存的是对象存储稳定 URL，而非浏览器临时地址。
3. 未满足发布门槛时，发布按钮不可用，并明确显示缺失项。
4. 发布后，训练列表和详情页能显示同一个版本的标题、封面、视频、步骤卡、拍摄要求和常见错误。
5. 患者选择“骨盆倾斜”或“膝关节旋转”时，不再看到“缩腹运动”的固定内容。
6. 患者点击“立即录制”直接打开相机；点击“从相册选择”直接打开相册。
7. 视频上传后必须进入上传确认页，由该页完成拍摄质量检查与分析确认。
8. 教学视频或图片加载失败时，页面有可理解的文字兜底，不阻塞患者继续训练。
9. 管理端预览的页面结构、字段映射、内容顺序与患者端一致。
10. 已发布版本可查看历史并可回滚，回滚后不丢失审计记录。

这套设计的本质是把“指导内容”从一组散乱文本和 URL，升级为可维护、可预览、可发布、可回滚的**患者训练教学内容包**。
